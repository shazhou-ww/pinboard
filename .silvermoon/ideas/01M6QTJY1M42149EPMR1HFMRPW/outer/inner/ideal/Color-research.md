# 全局同调配色调研与方案

调研日期：2026-11-06。本文是构想阶段的设计依据；[HTML 样稿](./color-proposal.html)用于比较配色，不是已实现的产品页面。

## 现状与根因

[背景选择](../../../../../../apps/web/src/background.tsx)已有
`mist`、`sand`、`ice` 三套预设，通过根元素的 `data-background` 切换，并使用
`pinboard:background` 保存。当前背景切换不需要新机制。

[全局样式](../../../../../../apps/web/src/styles.css)只为背景抽取了四个变量。其余大量界面颜色仍是固定值，所以不是几个按钮漏改，而是背景与界面颜色没有共享角色映射：

| 表面                     | 现有颜色示例                               | 问题与处理方向                                     |
| ------------------------ | ------------------------------------------ | -------------------------------------------------- |
| 主操作与浮动添加按钮     | `#294D38`                                  | 仍是深绿；随背景映射强调色                         |
| 次级操作、头像、菜单悬停 | `#E9EEE5`                                  | 淡绿仍散布于导航与交互；使用同调轻量底             |
| 卡片预览、详情、拖放层   | `#EDF2E8`                                  | 大面积浅绿尤为明显；改用低饱和预览底               |
| 面板与卡片信息层         | `#FFFEFA` 及其透明变体                     | 偏暖白与冷背景脱节；提供同调近白色，透明层单独检查 |
| 正文、次要文字、目录图标 | `#23332D`、`#6B796B` 等                    | 深浅绿灰累积色偏；提供同调中性色                   |
| 边界与焦点               | `#CDD5C9`、`#337758`                       | 强调色与背景分离；区分装饰边界、必要控件边界和焦点 |
| 成功、警告、错误         | `.success`、`.oauth-warning`、`.notice` 等 | 按语义保留，不能全局搜索绿色并替换                 |

覆盖范围应包含收藏墙、登录首页、管理与设置弹窗、账户菜单、分享页、公开发布及历史页、OAuth 授权页；不能只验证已登录首页。图片、文件缩略图及内容自身的颜色不参与重新着色。

## 一手资料与取舍

| 资料                                                                                                       | 借鉴什么                                                   | 不直接照搬什么                                           |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------------- |
| [Material Design 3：颜色角色](https://m3.material.io/styles/color/roles)                                   | 按用途区分主色、承载面、面上文字、轮廓；前景与背景成对设计 | 不采用整套 Material 组件外观，也不引入运行时取色         |
| [Radix Colors：色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) | 背景、悬停、选中、边界、实色按钮、文字应分层               | 不把其 APCA 指标当作 WCAG 2.2 比值通过证明，也不新增依赖 |
| [WCAG 2.2：文本最低对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)              | 普通文本至少 4.5:1，大字号至少 3:1；按未舍入比值判定       | 不用“看起来够深”代替计算；不声称整站已合规               |
| [WCAG 2.2：非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)               | 识别控件或状态所必需的视觉线索至少 3:1，焦点需清晰         | 不要求每条装饰分隔线都达到 3:1；禁用控件属于例外         |

推荐采用**已有背景预设 + 显式语义化角色配置**。这比运行时从渐变自动取色更易验证，也比所有背景共用一个蓝色更贴合现有三套背景。只调整颜色，不更换字体、不改变卡片结构、不新增主题编辑器。

## 配色方向

三套方案是三个现有背景的配套配置，不是三种互斥产品改版。名称确定为「晨光雾屿」「玫瑰沙丘」「晴空冰海」，默认仍为晨光雾屿。

| 展示名称 | 内部标识（保持不变） | 配色描述                   |
| -------- | -------------------- | -------------------------- |
| 晨光雾屿 | `mist`               | 雾蓝紫背景／雾靛强调色     |
| 玫瑰沙丘 | `sand`               | 沙色玫瑰背景／灰玫瑰强调色 |
| 晴空冰海 | `ice`                | 银灰冰蓝背景／深冰蓝强调色 |

| 角色              | 晨光雾屿              | 玫瑰沙丘              | 晴空冰海              |
| ----------------- | --------------------- | --------------------- | --------------------- |
| 原背景起点 → 终点 | `#E6EDF3` → `#E8E3EF` | `#F0E9E1` → `#EDDFDF` | `#ECEEF0` → `#DDEAF0` |
| 面板与信息层      | `#FAFBFE`             | `#FDFAFB`             | `#F8FBFD`             |
| 预览底／次级底    | `#EEF0F7`             | `#F5EDEF`             | `#EAF2F6`             |
| 正文              | `#283044`             | `#3D3038`             | `#27353E`             |
| 次要文字          | `#515971`             | `#69555F`             | `#4B606E`             |
| 强调色／焦点      | `#505C86`             | `#794C62`             | `#32677D`             |
| 主操作悬停        | `#414D75`             | `#70435A`             | `#27576C`             |
| 主操作按下        | `#354163`             | `#60364C`             | `#20495C`             |
| 轻量悬停底        | `#E3E7F2`             | `#EEE1E6`             | `#DCEAF1`             |
| 选中底            | `#D9E0F0`             | `#E8D5DF`             | `#CEE2EC`             |
| 装饰边框          | `#CBD0DF`             | `#DFCCD5`             | `#C5D6E0`             |
| 必要控件边界      | `#7A829C`             | `#9B778A`             | `#6D8899`             |

设计原则：

- **让背景保留存在感。**
  不改四个背景颜色，不把添加按钮做成高饱和亮色，不让所有卡片都变成深主色块。
- **保持内容的中性承载面。** 正文、目录与代码预览只染很轻的色；图片不受影响。
- **暖色不等于橘棕。**
  沙色背景已经包含玫瑰色，以低饱和灰玫瑰承接，而非另加陶土色。
- **不让状态靠主题猜。** 成功 `#286044 / #EDF6EF`、警告
  `#79500D / #FFF4DC`、错误 `#A13645 / #FCEEF0`
  固定使用前景／背景配对；同时配文字或符号，删除操作明确标注。
- **颜色提案不夹带布局改版。**
  样稿沿用收藏卡片、浮动添加按钮、菜单与授权面板这些真实元素；桌面并排只是方便比较颜色。

## 如何查看样稿

直接用浏览器打开
[color-proposal.html](./color-proposal.html)，无需服务、联网、登录或依赖安装。

- 切换三套背景，观察卡片、添加按钮、输入框、菜单与状态。
- 勾选“在样稿中对照旧绿色”，比较同一背景的新旧配色。旧配色是缩略模拟，不是生产截图。
- 使用 Tab 查看焦点；按钮支持悬停与按下，菜单可切换选中项，授权面板可打开、关闭。操作只作演示，不调用 API、不保存数据。
- 下方提供六色基准、完整角色表及三套方案的关键组合对比度；样稿实时计算比值。

## 验证边界与落地建议

HTML 中的关键组合检查涵盖普通文字、次要文字、主按钮三个状态、轻量底上的强调文字、输入框边界、焦点和语义状态。背景渐变使用 sRGB 不透明端点，取四个背景端点中的最小比值作为保守检查；文字承载面为不透明颜色。

已在 Windows 的无头 Microsoft Edge
157.0.4341.36 中验证样稿。三套方案的 27 项分组检查全部通过；下表显示各组最小比值，仅展示值四舍五入，判定使用原始数值。初稿中灰玫瑰选中底上的强调文字、部分次要文字未达 4.5:1，已加深相关色值，而不是降低验收阈值。

| 检查项                   | 晨光雾屿 | 玫瑰沙丘 | 晴空冰海 | 要求  |
| ------------------------ | -------- | -------- | -------- | ----- |
| 正文／面板               | 12.71:1  | 12.06:1  | 12.14:1  | 4.5:1 |
| 次要文字／全部受测界面底 | 5.03:1   | 4.90:1   | 4.90:1   | 4.5:1 |
| 白字／主操作各状态       | 6.53:1   | 6.95:1   | 6.23:1   | 4.5:1 |
| 强调文字／轻量底         | 4.93:1   | 4.97:1   | 4.66:1   | 4.5:1 |
| 输入框边界／面板         | 3.69:1   | 3.75:1   | 3.59:1   | 3:1   |
| 焦点环／全部受测界面底   | 4.72:1   | 4.97:1   | 4.64:1   | 3:1   |

固定语义色的文字／底色比值分别为：成功 6.68:1、警告 6.48:1、错误 5.95:1。三套背景均通过切换、旧绿色对照、语义色不变、菜单选中、授权弹窗 Escape 关闭与焦点归还、添加按钮聚焦输入框、保存演示反馈及焦点样式检查。每套背景分别在 1440、1000、768、390、320
CSS 像素宽度检查，页面无横向溢出；桌面与移动端截图检查通过。加载与操作未产生脚本错误或外部网络请求。

这不等于生产界面的全面无障碍证明。现有顶部栏、卡片信息层、弹出菜单含半透明或模糊背景，实际合成颜色会受到图片和内容影响。实施时必须检查这些真实场景；若不能保证可读性，应提高承载层不透明度，不能仅套用纯色对比度报告。

建议实施时继续使用现有 `data-background`
和保存机制，在同一份全局样式中按角色定义变量；不要按页面复制调色表，也不要通过批量替换十六进制值误改语义色。实施验证应覆盖各入口的初次加载、切换、刷新与页面跳转。
