# Implementation

实现范围、逐项接入与验证边界见[实施证据](./Implementation-evidence.md)。本阶段不修改已认可的理想世界，不创建生命周期事件，也不发布或改变部署种子。

## Steps

### I-S01: 盘点配色与页面覆盖

以现有 `background.tsx`、全局 `styles.css`
与路由入口为入口，盘点首页及登录、收藏预览及详情、菜单与设置、分享、发布及历史、OAuth 授权的颜色与交互状态。按装饰角色、独立语义状态及不可重新着色的原始内容分组，覆盖清单记录在实施证据中。

### I-S02: 统一配色规则与组件接入

保留 `data-background`、`mist / sand / ice` 及 `pinboard:background`
的选择与持久化机制。在同一份全局样式中精确实现已认可的三套调色表和语义化角色；使用「晨光雾屿／玫瑰沙丘／晴空冰海」搭配英文说明。统一实色、悬停、按下、选中、聚焦及禁用状态；成功、警告、错误与危险操作使用独立配对，不改变内容或布局。

对图片及文字内容上方的磨砂层保留原有透明度、模糊和展开行为，不得用接近不透明的统一底色遮盖磨砂效果；为图片上的键盘焦点保留实色隔离带。可读性检查区分主题底、较密浮层与任意图片，不宣称低透明度磨砂能保证任意图片下的最坏对比度。

### I-S03: 验证视觉一致性与功能回归

扩展现有 Vitest 测试，覆盖准确调色值、角色完整性、语义色独立性、实色与较密浮层的对比度、原始透明度与模糊分层、现有预览结构与保存行为。对比真实画面确认底层内容仍有可见贡献，而不只断言 blur 存在。更新直接相关的 README，并运行定向测试与
`pnpm check`。协调方另行进行浏览器实测；仅记录实际得到的证据和未验证边界。

## Acceptance criteria

### I-AC01: 装饰色完整接入

通过覆盖清单、样式检查及各背景下的页面截图，证明添加按钮、卡片及其他界面装饰不再残留脱节的旧绿色，语义色和内容颜色未被误改。

### I-AC02: 切换与保存行为一致

通过浏览器操作及适当的自动化测试，证明背景切换同步影响各页面与控件状态，刷新和跳转后仍保留选择，既有功能无回归。

### I-AC03: 可读性与项目检查通过

对各背景下普通文本验证至少 4.5:1 的对比度，大字号文本及必要控件边界、焦点指示验证至少 3:1；结合键盘检查证明焦点与语义状态可辨，并通过
`pnpm check`。
