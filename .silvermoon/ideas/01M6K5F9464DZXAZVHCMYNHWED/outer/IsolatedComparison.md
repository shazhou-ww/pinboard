# 隔离真实 R2 旧/新读取对照协议

## 目的与证据边界

原生产 rollout 没有采集指定 128 文件/8
MiB 样本的旧版实测，不能倒造历史。本次按用户另行授权，在当前真实 Cloudflare 资源中复现两种存储读实现，保留原来的同样本对照目标。它不是历史生产时点、完整旧应用部署、生产鉴权或写入性能的重放。生产上传/新旧内容可用性证据继续引用
[ProductionEvidence.md](ProductionEvidence.md)。

## 已授权资源与安全边界

- 只新建 1 个临时 Worker、1 个临时私有 R2 桶、1 个临时 D1 库，名称带
  `pinboard-car-verify-261106-` 与本次唯一后缀；先确认不存在，再记录实际 ID。
- 两种物理表示共用该临时桶；D1 仅准备读取所需的 `car_dags`、`car_blocks`
  及索引等必要 schema。不复制生产数据库，不插入合成账户、API
  Token、OAuth 或生产 Pin。
- 临时 Worker 仅允许读取本次白名单夹具及必要的受保护诊断，不暴露任意写入或远程 CID 获取。如需访问凭据，只生成临时、最小用途凭据，通过安全通道配置，不复用真实应用凭据或记录值。
- 约 25
  MiB 指云端固定样本的两种物理表示；受控存储操作最多 5000 次，达到上限或出现不可核查的成本/权限扩展需求时停止，不自动加量或升级付费计划。
- 生产 Worker `pinboard`、桶 `pinboard-blocks`、D1
  `9f15fd50-e103-459f-9f3f-9db3036f91de`
  和历史旧 UUID 禁止作为本实验写入/删除目标。临时部署不是生产 release，不创建或重推生产 tag，不修改生产路由/secret。

## 测量与独立校验

每组每种表示的 CAR 与选定 raw 块，首个唯一查询请求为冷候选，再同 URL 暖重复至少 5 次。旧/新表示交替测量，记录 UTC、方法、请求路径、HTTP 状态、实际首个 body
chunk 和总耗时、字节数、ETag/缓存头、CF-Ray/机房。统计中位数、范围及新/旧比值；任何失败或退化单独呈现，不混入成功时延。不保证 R2 内部冷缓存；不同机房的数据不冒充严格同机房配对。

每次 CAR 下载独立核对根、块集合、全部 CID/载荷；选定范围及空块真实读取必须匹配源字节。两种表示各在新建离线 Kubo 仓库重建，逐文件对比固定源清单，不从外网补块。

R2 操作数优先取平台 traces/查询。可同时记录临时 Worker 对**真实 R2 binding**
的成功/失败调用计数作交叉核对，必须标明是实际绑定调用而非本地 mock 或计费请求数。平台 span 缺失明确记为未观测，不能推断为 0 或由时延补算。记录旧块对象字节和、实际 CAR 对象字节、索引逻辑字段；独占临时 D1 的 seeding 前后页分配差只报告为该 schema 的整体数据/索引分配增量，不外推生产单块成本或当作 R2 复制/计费字节。

## 结束与清理

先将协议、工具来源/哈希、原始结果、结论和资源收据同步至 primary，再删除这次明确新建的临时资源。清理前核对名称、实际 ID、对象白名单与创建收据；发现非本次内容则停止，不广泛递归清空。控制面确认 Worker、桶和数据库已删除，临时凭据失效；清理失败明确记录，不声称完成 D-S03。只有所有当前 D-* 工作完成、证据有效且同步后，才记录准确修订的 submitOuter，随后按 CLI 呈现正式人类验收；资源授权和代理勾选均不是 acceptOuter。
