# Implementation

这是准备阶段的可调整初版，不表示已经实现。技术取舍见
[技术方案](Filtering-Design.md)。

## Steps

### I-S01: 建立完整元信息过滤查询

为现有列表增加可选关键词，在账户权限和删除条件内先匹配再分页；统一字面匹配及大小写规则，覆盖根节点描述与发布快照，并保持空查询兼容。

### I-S02: 接入顶部过滤交互

在 AccountManager 持有输入与查询状态，通过现有 header 渲染接口接入居中输入框；覆盖窄屏、输入法、请求竞争、清空、失败和列表操作后的刷新。

### I-S03: 验证边界与回归

补充服务端匹配、跨页与权限测试，以及前端输入、异步状态和卡片操作回归；运行仓库检查并进行响应式浏览器验证。

## Acceptance criteria

### I-AC01: 匹配完整且边界准确

自动测试以超过 50 条的列表证明跨页命中；覆盖两类 item、名称或描述、大小写、中文、内部空白、字面
`%`/`_`、空值，以及 CID、子节点、旧快照和其他账户的反例。

### I-AC02: 交互和异步状态可信

组件或浏览器测试证明输入法确认后过滤、旧请求不覆盖新结果、分页不混用关键词、失败不是空结果、清空恢复列表；在 320px、768px、1440px 视口和长账户名下检查无重叠、焦点和清空操作。

### I-AC03: 现有行为与数据一致性保持

通过现有 API/管理界面回归及新增写入一致性测试，证明省略关键词仍保持原行为，元信息变更后过滤结果及时刷新；`pnpm check`
通过。若需要数据库迁移，额外证明回填、重复运行安全及旧数据可检索。
