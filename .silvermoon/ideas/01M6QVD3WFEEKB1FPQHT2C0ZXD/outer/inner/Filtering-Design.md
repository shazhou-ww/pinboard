# 元信息过滤技术方案

## 方案选择

复用 `/api/pins` 与 `/api/publications` 的可选
`q`，由服务端匹配后分页，保持原来的排序、50 条页面大小和两种独立游标。不新增统一搜索端点、FTS、相关性排序、浏览器全量下载或卡片详情补取。

实施未采用准备阶段建议的派生投影。投影需要迁移、Unicode 回填和全部写入面的同步维护，而任意位置子串仍无法由普通索引加速。首版直接在 Worker 读取当前账户、有效状态及 cursor 之后的权威元信息，使用 JavaScript
`trim().toLowerCase()` 与
`includes`，然后才截取 50 条并用第 51 条确定游标。这不是先取 50 条再过滤，也不是客户端筛选。

## 元信息来源与一致性

Pin 的单条 SQL 查询读取原有卡片元信息与用户根描述，描述同时约束 account_id、root_cid、node_cid=root_cid。Publication 的单条候选查询关联 current_revision，并通过
`json_each` 精确取当前根 CID 对应的单个快照值，不匹配整个 JSON、子节点或正文。

名称与描述分别匹配，不跨字段拼接；缺失描述为空字符串。百分号、下划线、引号、正则等均无语法含义。大小写比较不经过 SQLite
`lower` 或 `NOCASE`；不做 locale、重音、兼容字符或繁简归一化。内部空白原样保留。

空查询仍使用原来的 SQL LIMIT
51 快路径。非空候选元信息来自单条数据库语句，应用层匹配后才结果分页。Publication 仍按原行为仅为最终最多 50 张卡片读取详情，不逐项获取候选详情。HTTP 返回原有卡片契约，Pin 辅助根描述不会泄漏到响应。

没有新表、派生列、索引、迁移或回填，历史数据立即可检索。HTTP/MCP/CLI 共用的权威 service 写入不需要双写。名称/描述修改、发布、回滚、转换、删除和恢复后，下一次查询直接反映权威状态。私有草稿不会改写发布快照。新增 service 测试覆盖上述生命周期，未执行生产数据库操作。

## API 与输入限制

省略或空白 q 保持兼容。共享契约导出归一化函数及 200 长度上限，HTTP/service 通过同一 schema 显式校验；输入框使用 maxLength。长度按 JavaScript
UTF-16 code unit 计数，与现有名称和浏览器约束一致。

两类列表分别保留 CID/ID 排序；描述匹配不会排在名称匹配之后。两个 HTTP 列表均使用 private,
no-store；不新增查询缓存、COUNT 接口或关键词日志，不把已加载数量误称为全账户总数。

## 前端接线

AccountManager 使用独立 `useItemLists`
hook 管理原始输入、当前查询、两个列表与游标、统一忙碌和错误状态。renderHeader 增加 ReactNode 槽位，HomeHeader 接收可选 filter，不新增全局 store。

输入 200ms debounce，Enter 立即应用；IME
composition 期间不发中间请求，结束后计时。清空立即请求普通首屏并恢复输入焦点。Escape 只由输入框消费，不添加全局快捷键。过滤不占用全局 busy，也不触发 tokens 拉取。

每次输入同步取消计时器和 AbortController，替换请求身份；新查询、refresh 和加载更多均检查请求身份与 abort 状态。即使传输层无视取消，旧响应也不能覆盖或追加到新条件。旧卡片只在明确的忙碌提示下暂留；两种新列表同时成功后整体替换。任一接口失败进入明确错误/重试，不显示“无匹配”或成功半页。加载更多携带同一当前 q/cursor；加载与失败时禁用两个入口。

名称、根描述保存、上传、发布、转换、回滚、删除、恢复后重新查询当前条件。不直接 prepend 不匹配的新卡片；上传成功提示可清空筛选查看。详情选择独立于可见列表，不因卡片不再匹配而突然关闭。

操作选择器不受卡片墙筛选影响：`useActionItems`
在上传或 Publication 对话框打开时按需读取不带 q 的列表、跟随分页游标，并独立维护加载、失败与重试。关闭或切换对话框会取消旧选项请求；输入筛选关键词不会重拉或替换目的地选项。Publication 发布目的地及既有 Pin 建议同样使用独立数据。上传在提交时解析并固定目的地对象，避免上传完成后因卡片墙变化丢失选择。

## 布局与性能边界

沿用 Instrument
Sans、现有主题背景、文字 #23332d、输入表面 #fffefa 与焦点边线 #294d38，不新增字体、强调色或装饰。桌面输入宽 360、高 40，绝对定位相对视口真正居中；不足 960px 时改为 120px 两行标题栏，输入与清空触控高度 44，同步正文留白与滚动偏移。长账户名截断，卡片墙保持主角。

非空查询需在 Worker 读取 cursor 后全部候选元信息，CPU、内存及 D1 读行数随账户规模线性增长；响应仍只有最多 50 张卡片。这降低迁移与一致性风险，不表示任意规模都有恒定成本。当前自动测试为 105 项，不能替代生产量级压测；极大账户应在发布前评估 D1 单次结果大小、Worker 内存及延迟。如规模触及限制，后续需有实测依据再选择投影或分批扫描，不能改为只筛选已加载卡片。
