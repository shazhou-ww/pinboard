# Implementation

本契约仅为可调整的实施初版，所有步骤尚未执行。本次只整理构想，不开始实施；若后续获准推进，再细化具体设计。

## Steps

### I-S01: 验证标准接口与本地取数边界

验证目标 Kubo 版本的请求、轮询与错误处理，特别是无 Bitswap
delegate 的实际行为和规范差异；明确连接器本地读取与联网获取的授权边界。

### I-S02: 接入账号连接器与持久化任务

在既有鉴权、CAR 验证和存储能力上，增加账号隔离的连接注册、内容探测、任务分配及上传关联。确定断线、撤销、重试、取消和重复提交的行为，不暴露任意 RPC。

### I-S03: 补齐工作流与回归验证

验证标准接口适配、任务与账户 pin 引用关系、本地连接器操作及失败状态，并保持现有 CLI、Web、MCP 和公共读取路径不变。

## Acceptance criteria

### I-AC01: 本地独有内容可以完成持久化

通过独立本地 Kubo 与连接器的端到端测试，证明从 CID 请求到完整 DAG 入库的路径；停止来源后仍能从 Pinboard 下载并校验相同内容。

### I-AC02: 失败与授权边界可验证

通过设备离线、根存在但缺子块、断线、撤销、跨账号请求、取消后迟到上传与无效 CAR 测试，证明不会越权或错误报告
`pinned`。

### I-AC03: 兼容结论与回归有证据

记录具体 Kubo 版本的兼容实验和标准 schema 验证结果，明确未满足项；运行相关测试与仓库
`pnpm check`，证明原有行为未退化。
