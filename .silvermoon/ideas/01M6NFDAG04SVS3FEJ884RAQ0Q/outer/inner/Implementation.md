# Implementation

本契约仅为可调整的实施初版，所有步骤尚未执行。本次只整理构想，不开始实施；若后续获准推进，再细化具体设计。

## Steps

### I-S01: 验证标准接口与执行节点边界

验证目标 Kubo 版本的请求、轮询、错误处理及真实 Bitswap
delegate 的可达性与服务窗口；明确节点池联网取数和账号连接器本地读取的权限差异。

### I-S02: 接入取数节点与持久化任务

在既有鉴权、CAR 验证和 R2 存储上，增加节点注册、健康容量、任务租约及上传关联；明确断线转交、迟到结果、撤销、取消与多账号隔离，不暴露任意 RPC。保留账号设备连接器模式的边界，具体初版范围后定。

### I-S03: 补齐工作流与回归验证

验证标准接口适配、任务与账户 pin 引用关系、节点执行及失败状态，并保持现有 CLI、Web、MCP 和公共读取路径不变。

## Acceptance criteria

### I-AC01: 在线副本独立于来源和执行节点

通过独立来源 Kubo、取数节点及 Pinboard 的端到端测试，证明只有完整 DAG 入库 R2 后才报告成功；停掉来源和执行节点后仍可下载并校验相同内容。

### I-AC02: 失败与授权边界可验证

通过无可用节点、缺子块、断线转交、租约过期、撤销、跨账号访问、取消后迟到上传与无效 CAR 测试，证明不会越权、覆盖有效任务状态或错误报告
`pinned`。

### I-AC03: 兼容结论与回归有证据

记录具体 Kubo 版本的兼容实验和标准 schema 验证结果，明确未满足项；运行相关测试与仓库
`pnpm check`，证明原有行为未退化。
