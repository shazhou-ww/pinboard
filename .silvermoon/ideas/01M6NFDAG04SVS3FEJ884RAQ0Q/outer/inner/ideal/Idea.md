# 通过账号下的本地连接器支持远程 Pin

## 问题

Pinboard 希望接入 Kubo 的远程 pin 工作流，但 Worker 不运行 Kubo，也无法直接从用户本地节点通过 P2P 获取内容。仅提交 CID 不会上传数据。

## 结果

增加面向标准 Pinning Service
API 的接口，让服务通过同账号客户端主动建立的长连接寻找内容，再接收、验证并持久化完整 DAG。取得不到内容时明确报告失败。

## 边界

- 服务端不运行 Kubo/P2P 节点；只调度请求账号授权的连接器，不公开本地 Kubo RPC。
- 保留独立 CLI 和现有上传、读取能力；连接器为可选常驻能力，不要求所有客户端安装 Kubo。
- 当前仅记录构想，不实施、不部署；严格标准兼容与具体传输设计仍须验证。

## 验收标准

- 方向覆盖“仅存在于本地 Kubo 的内容”，并明确设备离线、缺块和取数失败时的结果。
- 只有完整 DAG 经服务端验证并持久化后才可报告 `pinned`，接受请求不等于成功。
- [方案与待验证事项](./connector-design.md)明确账号隔离、连接授权以及 Kubo 可用性与严格标准兼容的区别。
