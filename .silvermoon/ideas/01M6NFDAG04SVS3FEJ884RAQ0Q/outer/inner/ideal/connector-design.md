# 账号级本地 Kubo 连接器：方案与待验证事项

本文支持
[构想契约](./Idea.md)，记录讨论中需要保留的机制、风险与未决问题，不构成已经选定的实施架构或已验证的兼容承诺。

## 问题与关键判断

标准远程 pin 请求提交 CID，不传输内容字节。Kubo 可附带本地节点的
`origins`；传统服务通常通过 P2P 拉取完整 DAG。找不到 provider、来源离线或缺块都可能失败，标准并不保证任意 CID 一定可取到。

Pinboard 当前只对自身存储中已有的完整 DAG 增加账户引用，不会递归到互联网寻找缺失内容。已有的 Kubo
HTTP 读取能力是“Kubo 从 Pinboard 下载”，不能解决“Pinboard 从本地 Kubo 取数”。

本构想的核心是反转连接方向：用户运行一个可以访问本地 Kubo 的连接器，由它主动建立到账户服务的长连接。服务收到 pin 请求后，在该账号现有连接中寻找来源，而不是连接任意公网 P2P 节点。

## 候选交互

```text
标准 API 客户端 / Kubo
          |
          | 提交 CID，查询任务状态
          v
Worker Pin API ---- 账号连接协调器
                         |
                         | 长连接探测、任务与进度
                         v
                 本地 Connector ---- 本机 Kubo RPC
                         |
                         | HTTPS 上传完整 CAR
                         v
                 服务端验证 ---- R2 / D1
```

连接器可以是独立程序，或独立 CLI 的可选常驻子命令；目前不决定包装形式。它直接调用本机 Kubo
HTTP RPC，不要求 CLI 转为包装 `ipfs`
命令，也不改变现有无需 Kubo 的上传、下载能力。

建议长连接仅承载控制消息，CAR 通过有界 HTTPS 上传进入既有校验路径。账号级 Durable
Object 与休眠 WebSocket 是候选协调机制，不是既定依赖。具体额度、费用、消息限制和恢复方式需在实施前验证。

## 一次 Pin 的候选流程

1. 鉴权后持久化请求，生成不透明 `requestid`，初始为 `queued`。
2. 在请求账号的在线连接中有界并行探测 CID；没有连接时按明确期限等待设备上线，而不是无限等待。
3. 选择一个可用来源并进入
   `pinning`，授权它执行该请求的 DAG 导出和上传。其他来源可作为断线或缺块后的候选，不必同时重复上传全部数据。
4. 连接器读取本机 Kubo 并导出保留原始 blocks 的 CAR。拥有根 block 不代表拥有完整 DAG；探测结果只是提示。
5. 服务端独立校验根 CID、每个 block 的哈希、支持的编码及完整 DAG 闭包，遵守现有资源限制；所有必要内容持久化并建立账户引用后才能报告
   `pinned`。
6. 来源缺块、断线、上传无效或资源超限时进行有界处理，最终报告 `failed`
   和可理解的原因。截止时间、退避与重试策略待定；标准没有统一超时。

不能把文件下载后重新编码当成同一 CID 的归档。任务被接受、来源声称拥有内容或上传开始，都不能作为 pin 成功的证明。

## 长连接不是可靠队列

连接可能因休眠、网络切换、程序退出或平台维护中断；必须支持重新认证、重连和任务重新认领。任务状态、截止时间和归属不能仅保存在进程内存中。

需要在后续设计中解决重复探测、重复上传、来源切换、取消和删除后的迟到结果，以及替换 pin 期间旧引用的保留。连接器声明任务成功不具有权威性；服务端入库与引用状态才是依据。

若多个来源都只有部分 blocks，初版是否允许组合获取尚未决定；不能因为各自存在根 block 就承诺能够补齐整个 DAG。

## 授权、安全与公开内容

- 连接注册、任务分配、状态查询和上传都绑定服务端认证出的账号。外部调用者不能传入账号标识来枚举或调度他人的设备。
- 连接器授权应单独可撤销，并与普通 API
  token 的权限边界一致；现有 token 是否可复用、是否需要设备级凭证待定。
- 只提供受限的 CID 探测、DAG 导出和任务反馈能力，不建立任意 Kubo
  RPC、shell、文件路径或任意 URL 的远程代理。
- Kubo
  RPC 保持本地可达，不向公网开放。账号凭证被撤销后，已有长连接也必须失去调度和上传授权。
- 上传授权绑定账号、任务、目标 CID 和有效期；取消、删除或过期后，迟到上传不得重建 pin 引用。日志不记录凭证或内容字节。
- 注册连接器意味着允许服务按授权读取并公开上传相应内容，必须明确告知用户；内容可取到不代表用户同意公开。
- 继续遵循 Pinboard 的公开内容与保留政策，包括失败的部分写入也可能公开。此构想不承诺私有存储或删除所有网络副本。

## 必须保留的产品边界

| 情况                      | 预期边界                                            |
| ------------------------- | --------------------------------------------------- |
| 内容已完整存在于 Pinboard | 可以复用存储并建立引用，无需客户端在线              |
| 内容只在同账号在线 Kubo   | 通过获授权连接器导出并上传                          |
| 设备全部离线              | 有限等待，超过期限后明确失败                        |
| 根存在但缺子块            | 不报告成功；尝试其他来源或失败                      |
| 内容只在其他账号设备      | 不跨账号探测；已有公开存储的复用不等于跨账号调度    |
| 只有公网 P2P provider     | Worker 不直接获取；连接器是否允许联网获取需另行授权 |

“只读取本地 blocks”与“让本地 Kubo 继续联网寻找内容”是不同模式。部分 Kubo 读取操作可能触发网络获取，因此不能仅靠连接器名称或调用 RPC 的位置宣称本地限定；需验证具体调用能否约束为离线读取。默认策略尚未选定。

公共 HTTP 网关可以是未来独立的数据来源，但不是本构想完成本地独有内容入库的前提，也不作为隐式回退。

## 标准 API 兼容风险

面向标准的接口至少涉及创建、列举、查询、替换和删除 pin 请求，以及状态、过滤、分页、元数据和错误格式；不是简单复用当前按 CID 管理的接口。应使用独立接口命名空间，避免改变现有客户端语义。

标准以 `requestid`
区分请求，同一 CID 可重复提交；当前账户 pin 以账号和 CID 唯一。后续必须明确多个请求与一个账户引用的关系，避免删除一个请求时误删其他有效引用，并定义与现有 CLI/Web 直接 unpin 的交互。

截至本次讨论核对的 Pinning Service API 1.0.0 schema，`PinStatus.delegates`
必填，且至少有一个地址；语义是能通过 Bitswap 接收数据的节点。私有 WebSocket 连接器不是该节点，HTTP
provider 标识也不能冒充它。

因此，本方案解决取数路径，但不自动解决严格标准符合性。必须分别验证：

- 目标 Kubo 版本能否在没有有效 delegate 的情况下完成创建、轮询、列举与删除。
- 响应是否满足官方 schema；即使 Kubo 接受空数组，也不能据此声称严格兼容。
- 若严格兼容需要真实 Bitswap
  delegate 或上游规范调整，是否接受相应新增范围；未经决定不引入服务端 P2P 桥，也不伪造地址。

## 后续需要决定，但现在不实施

1. 目标是特定 Kubo 版本可用，还是严格符合标准；无 delegate 的限制是否可接受。
2. 连接器仅导出本地已有内容，还是允许本地 Kubo 联网取数；授权如何向用户呈现。
3. 离线等待、任务时限、并发与大小限制，以及超出现有上传能力时的明确失败行为。
4. 多设备来源选择、重复请求与账户引用的具体语义；是否需要跨来源补齐 DAG。
5. 连接器分发形式、设备撤销与服务停用流程；任何部署或发布另行授权。
