# 为 Pinboard 增加可迭代的发布项

## 问题

固定 Pin 和发布项已支持内容分享与版本迭代，但卡片之间缺少直观的引用和升级操作，数据节点也缺少与系统预览并列的用户描述。

## 结果

在已有发布能力上补齐卡片定向拖放、固定 Pin 转为发布项，以及数据节点的可选描述。名字归属 pinned
item（包括 publication），数据节点的描述部分则由用户 description 与系统 preview 两个独立字段组成；发布和引用不混淆名字、内容及展示信息。

## 边界

- 保持先上传、后按需发布的轻量流程，首版覆盖 Web、CLI、HTTP 和 MCP；公开读取不区分访客，管理写操作保留既有鉴权边界。
- 文件拖到已有固定 Pin 或 publication 上先确认创建或更新意图；已有 Pin 拖到 publication 是 link，不是 move。固定 Pin 可明确转为 publication；名字属于 item，加入另一个 publication 不继承来源名字，私有名字不自动公开。
- 内容 CID 的不可变性、统一尺寸卡片、公开历史、协商缓存、CAS/幂等、当前 CID 的 NOP、独立版本引用和 30 天最近删除继续有效。description 不因 preview 重建或清理丢失；不因本轮讨论预先决定描述进入内容 DAG、改变 CID 或修改描述必然产生新版本。

## 验收标准

- 文件拖到 publication 时确认新增版本；拖到固定 Pin 时可确认以原内容为 v1 创建 publication、以新内容为 v2。已有 Pin 拖入 publication 不重复上传、不移除来源 Pin、不改变双方名字；固定 Pin 可不上传而转为单版本 publication，取消不修改原项，非拖拽入口可完成同等操作。
- 固定 Pin 和 publication 版本引用的数据节点（包括目录内部节点）支持可选 description，并与 preview 同属节点描述部分；用户描述与系统生成预览独立更新，重新生成或清理预览不覆盖用户文字。名字仍属于 item，实际内容内的文件名与目录路径不受影响。
- 既有发布、回滚、缓存、鉴权、最近删除恢复与 GC 行为保持兼容；link 保留独立引用，转换不丢失内容或既有 CID 链接。转换后原位展示 publication，沿用自身名字须先确认其公开含义；具体元数据存储、编辑与跨引用作用域须在实施前明确，不伪装成已确认产品规则。
