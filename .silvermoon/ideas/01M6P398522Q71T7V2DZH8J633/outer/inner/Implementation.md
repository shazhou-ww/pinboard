# Implementation

首轮构想已实现并上线；当前修订补充卡片拖放、显式转换、节点描述与名字归属，用户已接受构想并授权自主实施与门禁审阅。当前轮次的独立审阅与证据列于各验收项开头；其后的首轮检查记录仅作历史背景。讨论背景见
[发布项与指针设计](./ideal/publication-design.md)；技术命名遵循现有代码，产品语义以已验收构想为准。

## Steps

本轮由用户明确委托一个实现 sub-agent，主 Agent 自主处理设计细化、差异审阅和全部门禁，不以委托代替验证。实施采用以下保守决策，保持 accepted
ideal 不变：

- 节点描述先使用独立持久元数据，与内容 CID 分离，不改写已有 DAG 或原始 CAR；普通 CID/CAR 导出保持原字节，API 提供描述以便客户端显式另存，不宣称原始内容归档自动携带描述。
- 用户 description 以账户、已保存根内容及其可达节点为管理上下文，不建立全局可写 CID 说明。根和子节点均可选纯文本描述，长度受限；同一 CID 在其他账户或其他根引用下不被连带改写。preview 继续由系统按实际节点 CID 生成，逻辑响应将 description 与 preview 并列，生成和清理绝不写用户字段。
- publication 发布时快照该次根及子节点描述，公开固定版本返回该快照；普通 Pin 的后续描述编辑不改写既有版本。首版不提供原地改写已发布版本描述：需要不同描述的新内容版本时使用正常发布流程；当前 CID 发布仍为 NOP，不用元数据编辑偷偷绕过版本规则。明确呈现这一限制，不把未应用的描述更改提示为发布成功。
- 原位转换为独立、可重试的管理操作，显式确认公开标题，原内容成为 v1；携带新文件时上传完成后发布 v2。来源静态卡片仅在显式转换成功后不再作为普通独立项展示，后端保留/交接须由事务保证，删除与恢复不能意外复活重复卡片或使其他引用失效。普通 link 永不转换或移除来源 Pin。

### I-S01: 建立发布模型和保留一致性

本轮先明确节点描述的持久化、导出、作用域、权限与编辑/快照规则，再实现 description 与 preview 两字段独立更新；保留 item 名字与数据节点的分层。设计未定前不假设需要改写内容 CID 或以描述编辑绕过既有历史语义。

增加发布项、不可变版本和受控指针更新，统一处理鉴权、并发、幂等、当前 CID 的 NOP 以及内容和预览引用。Pin 的 Unpin 和发布项删除采用默认 30 天最近删除，协调恢复、到期释放与 GC；保持公开 CID 和独立引用语义。

### I-S02: 接入发布入口和访问协议

本轮增加外部文件拖到卡片的目标确认、已有 Pin 到 publication 的 link，以及固定 Pin 显式原位转换；补齐非拖拽等价入口及 API/CLI/MCP 对应能力，保留公开名字确认、独立来源引用与部分成功提示。

首版通过共享服务完整接入 Web、CLI、HTTP 和 MCP 的已有 Pin 发布、上传并发布、删除、最近删除查询和恢复；提供当前版本、固定版本及统一公开历史和协商缓存。Web 沿用统一尺寸卡片展示静态 Pin 和发布项，以轻量标识区分发布身份、当前版本和历史数量，并提供最近删除列表。

### I-S03: 验证兼容性与故障边界

本轮新增定向拖放/取消、link 非 move、转换不丢链接、名字不传播及节点描述不被预览重建覆盖的证据；覆盖目录子节点和多引用边界，不沿用首轮通过记录勾选本轮要求。

补充发布、NOP、回滚、公开历史、缓存、管理鉴权、最近删除恢复与到期释放及 GC 竞态测试，更新直接相关使用文档并运行仓库检查。实现由独立 sub-agent 执行，主 Agent 依据本契约审阅实际差异、验证结果并负责集成，不以 sub-agent 的完成声明代替证据。

## Acceptance criteria

### I-AC01: 发布更新可控且可重试

本轮主 Agent 独立审阅了实际转换事务：先在同一 D1
batch 内建立发布项、v1 描述快照和保留引用，再删除源固定 Pin；不是靠客户端隐藏或将原 Pin 塞入最近删除。幂等结果包含真实事务时点的快照，来源删除失败会回滚完整交接，同请求可安全重试；仅显式转换要求既有
`pins:delete`，普通 link 不删除来源或覆盖双方名字。

真实浏览器使用生产 Web 构建和编译 Worker、隔离 Miniflare
D1/R2，只有本地身份展示/Token 列表由测试网关合成，所有业务变更使用实际 HTTP 服务。内部 Pin 拖到 publication 后实际新增版本、零上传且源名字/引用不变；文件拖到固定卡片先取消时零写入，再确认得到原 v1/新 v2且仅一次上传；文件拖到已有 publication 更新为 v3，标题不变。键盘菜单转换带子节点的 DAG，无上传、无重复静态卡片，v1 保留根/子描述。实际上传成功后仅注入发布 409，UI 明确给出保留 Pin、幂等请求标识及重试说明，当前版本未移动。

本轮以集成测试证明已有 Pin
link 不重复上传或删除来源、不传播名字；文件定向发布先确认，取消不修改，失败不移动指针；固定 Pin 转换得到原内容 v1，带新文件的转换再得到 v2，并保持原 CID 可读。原位转换与普通 link 的卡片/引用行为明确不同。

用服务和全部入口测试证明两种发布入口一致，上传或发布失败不移动指针，并发冲突显式返回，幂等重试不重复创建版本；当前 CID 重发不改版本、指针或发布时间，非当前历史 CID 重发创建新版本，NOP 重试也保持原结果。

证据入口：[Worker 发布与并发测试](../../../../../apps/worker/test/publications.test.ts)、
[真实 CLI 与 Worker 集成测试](../../../../../apps/worker/test/cli.test.ts) 和
[全入口使用说明](../../../../../docs/publications.md)。主 Agent 的真实 Chrome 验证使用生产构建 Web、隔离 Miniflare
D1/R2 及仅本地测试的合成身份，已完成 Web 创建 v1、选择发布项上传生成 v2、回滚到 v1 且保留两条版本、删除后公开历史 404、恢复原发布项及普通 Pin 的闭环；不在产品中加入开发登录或鉴权绕过。
