# Implementation

准备阶段的轻量实施初版，待构想验收后细化。讨论背景见 [发布项与指针设计](./ideal/publication-design.md)；其中接口名称和存储形状仍为建议。

## Steps

### I-S01: 建立发布模型和保留一致性

增加发布项、不可变版本和受控指针更新，统一处理授权、并发、幂等以及内容和预览引用，保留现有 Pin 语义。

### I-S02: 接入发布入口和访问协议

通过共享服务接入 Web、CLI、HTTP 和 MCP 的已有 Pin 发布与上传并发布；提供当前版本和固定版本访问及协商缓存。Web 沿用统一尺寸卡片展示静态 Pin 和发布项，以轻量标识区分发布身份、当前版本和历史数量。

### I-S03: 验证兼容性与故障边界

补充发布、回滚、缓存、授权和 GC 竞态测试，更新直接相关使用文档并运行仓库检查。

## Acceptance criteria

### I-AC01: 发布更新可控且可重试

用服务和接口测试证明两种入口一致，上传或发布失败不移动指针，并发冲突显式返回，幂等重试不重复创建版本。

### I-AC02: 访问与缓存符合版本语义

用 HTTP 和客户端测试证明当前链接跟随发布及回滚，固定版本保持不变，ETag 正确覆盖响应变化，撤销检查先于 304；用组件测试和响应式视觉检查证明两类卡片尺寸一致、发布项可辨，回滚时当前版本与历史数量不混淆。

### I-AC03: 既有行为和存活引用得到保护

用回归及 GC 竞态测试证明旧 Token 不扩权、普通 Pin 流程不变、发布引用保护完整 DAG 和预览；以 pnpm check 通过作为仓库检查证据。
