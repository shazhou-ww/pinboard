# Implementation

准备阶段的轻量实施初版，待构想验收后细化。讨论背景见
[发布项与指针设计](./ideal/publication-design.md)；其中接口名称和存储形状仍为建议。

## Steps

### I-S01: 建立发布模型和保留一致性

增加发布项、不可变版本和受控指针更新，统一处理鉴权、并发、幂等、当前 CID 的 NOP 以及内容和预览引用。Pin 的 Unpin 和发布项删除采用默认 30 天最近删除，协调恢复、到期释放与 GC；保持公开 CID 和独立引用语义。

### I-S02: 接入发布入口和访问协议

首版通过共享服务完整接入 Web、CLI、HTTP 和 MCP 的已有 Pin 发布、上传并发布、删除、最近删除查询和恢复；提供当前版本、固定版本及统一公开历史和协商缓存。Web 沿用统一尺寸卡片展示静态 Pin 和发布项，以轻量标识区分发布身份、当前版本和历史数量，并提供最近删除列表。

### I-S03: 验证兼容性与故障边界

补充发布、NOP、回滚、公开历史、缓存、管理鉴权、最近删除恢复与到期释放及 GC 竞态测试，更新直接相关使用文档并运行仓库检查。

## Acceptance criteria

### I-AC01: 发布更新可控且可重试

用服务和全部入口测试证明两种发布入口一致，上传或发布失败不移动指针，并发冲突显式返回，幂等重试不重复创建版本；当前 CID 重发不改版本、指针或发布时间，非当前历史 CID 重发创建新版本，NOP 重试也保持原结果。

### I-AC02: 访问与缓存符合版本语义

用 HTTP 和客户端测试证明当前链接跟随发布及回滚，固定版本保持不变，历史对所有人统一公开，ETag 正确覆盖响应变化，最近删除状态检查先于 304、恢复保留原链接；用组件测试和响应式视觉检查证明两类卡片尺寸一致、发布项可辨，回滚时当前版本与历史数量不混淆。

### I-AC03: 既有行为和存活引用得到保护

用回归、可控时钟及 GC 竞态测试证明旧 Token 不扩权、上传与 CID 分享兼容；Pin 和发布项删除均保留 30 天、期内可恢复、到期后不可恢复且仅释放自身引用，重复删除不延长窗口，发布引用保护完整 DAG 和预览，最后引用释放后才启动现有七天宽限期；以 pnpm
check 通过作为仓库检查证据。
