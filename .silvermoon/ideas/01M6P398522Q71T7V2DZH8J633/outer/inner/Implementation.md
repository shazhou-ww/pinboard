# Implementation

构想已验收，按 Web、CLI、HTTP 和 MCP 全入口实施。讨论背景见
[发布项与指针设计](./ideal/publication-design.md)；技术命名遵循现有代码，产品语义以已验收构想为准。

## Steps

### I-S01: 建立发布模型和保留一致性

增加发布项、不可变版本和受控指针更新，统一处理鉴权、并发、幂等、当前 CID 的 NOP 以及内容和预览引用。Pin 的 Unpin 和发布项删除采用默认 30 天最近删除，协调恢复、到期释放与 GC；保持公开 CID 和独立引用语义。

### I-S02: 接入发布入口和访问协议

首版通过共享服务完整接入 Web、CLI、HTTP 和 MCP 的已有 Pin 发布、上传并发布、删除、最近删除查询和恢复；提供当前版本、固定版本及统一公开历史和协商缓存。Web 沿用统一尺寸卡片展示静态 Pin 和发布项，以轻量标识区分发布身份、当前版本和历史数量，并提供最近删除列表。

### I-S03: 验证兼容性与故障边界

补充发布、NOP、回滚、公开历史、缓存、管理鉴权、最近删除恢复与到期释放及 GC 竞态测试，更新直接相关使用文档并运行仓库检查。实现由独立 sub-agent 执行，主 Agent 依据本契约审阅实际差异、验证结果并负责集成，不以 sub-agent 的完成声明代替证据。

## Acceptance criteria

### I-AC01: 发布更新可控且可重试

用服务和全部入口测试证明两种发布入口一致，上传或发布失败不移动指针，并发冲突显式返回，幂等重试不重复创建版本；当前 CID 重发不改版本、指针或发布时间，非当前历史 CID 重发创建新版本，NOP 重试也保持原结果。

证据入口：[Worker 发布与并发测试](../../../../../apps/worker/test/publications.test.ts)、
[真实 CLI 与 Worker 集成测试](../../../../../apps/worker/test/cli.test.ts) 和
[全入口使用说明](../../../../../docs/publications.md)。主 Agent 的真实 Chrome 验证使用生产构建 Web、隔离 Miniflare
D1/R2 及仅本地测试的合成身份，已完成 Web 创建 v1、选择发布项上传生成 v2、回滚到 v1 且保留两条版本、删除后公开历史 404、恢复原发布项及普通 Pin 的闭环；不在产品中加入开发登录或鉴权绕过。

### I-AC02: 访问与缓存符合版本语义

用 HTTP 和客户端测试证明当前链接跟随发布及回滚，固定版本保持不变，历史对所有人统一公开，ETag 正确覆盖响应变化，最近删除状态检查先于 304、恢复保留原链接；用组件测试和响应式视觉检查证明两类卡片尺寸一致、发布项可辨，回滚时当前版本与历史数量不混淆。

主 Agent 以真实 Chrome 在 1440 × 1000 与 390 ×
844 下检查了七张统一卡片，包括三个独立发布项和当前 v3
/ 共五版本状态：桌面卡片均为 319.75 × 239.8125，窄屏均为 346 ×
259.5；窄屏详情及最近删除对话框宽 352，内部无水平溢出。Shift+F10、方向键、End、Escape 和真实触摸输入均验证菜单可用及焦点返回；跟随、固定版本和 CID 的复制操作有独立标签。只读预览中的恢复操作明确报错，不伪装为真实写入成功。

### I-AC03: 既有行为和存活引用得到保护

用回归、可控时钟及 GC 竞态测试证明旧 Token 不扩权、上传与 CID 分享兼容；Pin 和发布项删除均保留 30 天、期内可恢复、到期后不可恢复且仅释放自身引用，重复删除不延长窗口，发布引用保护完整 DAG 和预览，最后引用释放后才启动现有七天宽限期；以 pnpm
check 通过作为仓库检查证据。

兼容性审阅发现并修复了旧独立块 Pin 不能直接发布的问题：完整旧 DAG 经已有存储写入护栏提升为索引 CAR，CID、私有标签和创建时间不变，再由相同原子就绪检查建立保留引用。真实 D1/R2 测试覆盖缺块、损坏、GC 抢占暂停中的写入、安全重试，以及源 Pin 到期后发布事务的拒绝。

主 Agent 最终执行完整
`pnpm check`：格式、release 校验、全工作区 lint/typecheck/test/build 及独立 CLI
tarball 离线安装均通过。测试结果为 contracts 2、encoding 14、Web 140、CLI
160（另 2 跳过）、Worker
174（另 1 跳过）；Worker 分支覆盖率为 92.36%，未降低原有 90% 门槛。Windows 凭据安全测试使用仓库已有的
`PINBOARD_TEST_ROOT` 指向私有会话目录；验证由 `pnpm dlx pnpm@11.22.0 check`
启动，避免原生 pnpm 可执行文件与现有 CLI 打包脚本的 Node 启动方式不兼容，不修改产品凭据保护或依赖。
