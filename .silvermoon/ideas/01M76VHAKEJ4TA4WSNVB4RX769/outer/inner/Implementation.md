# Implementation

## Steps

### I-S01: 收敛 Publication 密钥与记录生命周期

明确托管、备份恢复、TTL/EOL/续签、私有指针和删除恢复策略，设计业务提交与签名记录的一致性；需真实迁移时单独申请授权。当前只有构想重定义授权，不实施密钥或 schema。

### I-S02: 实现标准读取适配并验证互操作

未来获准后实现 Publication 到稳定 IPNS
Name 的映射、原始记录 GET/HEAD，复用业务权限并保留管理及历史 API；不实现 DHT、UnixFS 路径或任意 IPNS 回源。

## Acceptance criteria

### I-AC01: 签名指针与生命周期可证明

独立客户端验签及版本测试覆盖发布、回滚、续签、重启、过期、错名及篡改；续签不创建内容版本，删除不再服务或续签，失败/并发不发布错误 CID。

### I-AC02: 密钥与读取权限安全

验证无未授权更新、密钥不进入日志/响应、恢复后名称不变及私有指针不泄露；协商、缓存与原有 Publication/raw
API 回归通过。

### I-AC03: 最终候选通过完整检查

未来最终候选执行并通过 pnpm
check；候选变化后重新验证，不以元数据检查代替签名、业务及密钥安全证明。
