# Implementation

## Steps

### I-S01: 接入标准 CAR 与路径证明

复用现有 CID、索引存储和存活根授权能力，增加 GET/HEAD 标准 CARv1 路径证明。仅支持显式 dag-scope=block、version=1、order=dfs、dups=n；省略范围视为 all 并拒绝，唯独空 identity 探针允许无范围的仅头部 CAR。查询格式优先于 Accept，查询变体优先于对应媒体参数；未支持的 CAR 可回退到可接受的 raw，保留图片默认选择。支持普通 UnixFS/HAMT 路径及 DAG-CBOR 映射、列表、CID 链接和内联终值；保留原始块与 CIDv0/v1，不递归终点子树、不跟随符号链接、不套用 ZIP 文件名限制。

### I-S02: 验证预检失败与兼容性

通过有界预检在发送响应前构造证明：最多 256 块、32 MiB、单块 2
MiB，读取期间响应取消；HEAD 和 304 同样校验路径、存储可用性及哈希。补充独立解析与证明校验、缺块、篡改、限制及取消测试；同步 README 和 Kubo 能力文档。独立外部客户端、生产发布与浏览器验收由父任务完成，不在本阶段代替记录。

## Acceptance criteria

### I-AC01: 证明与实际响应一致

固定多级路径 fixture 的 CAR
block 集合、SHA-256/CID、根到路径关系由独立验证器检查，覆盖普通 UnixFS、实际 HAMT 子分片、DAG-CBOR 映射/列表/内联终值及 CIDv0；删除或篡改必须导致验证失败。错误路径、未授权根、探测、GET/HEAD 和条件响应有明确断言。

### I-AC02: 资源及已有接口保持边界

CAR 与 raw 使用相同的根可用性策略：未知或不可读根始终 404，已授权但缺失的根普通请求 404、only-if-cached 请求 412；GET/HEAD 和通配条件请求均遵守该策略，缺失路径仍为 404、子证明块及索引存储故障仍为 503。

故障注入证明缺块、损坏索引对象、存储异常、取消及资源超限不会成功输出不完整证明；拒绝不支持的范围/变体和不安全 URL 语法。raw、图片、自定义完整 CAR 及权限保持回归；不新增依赖、模式、远程获取或读取写入。

### I-AC03: 最终候选通过完整检查

最终候选版本运行并通过 pnpm
check；检查成功后若候选内容变化，必须重新执行并通过，不得用 silvermoon
check 替代。本项与 ledger 的 I-AC03 一致。
