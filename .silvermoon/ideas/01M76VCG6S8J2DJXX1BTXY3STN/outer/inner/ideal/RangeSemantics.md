# 局部读取与协商的已确认边界

本文件服务于 Idea.md。用户本轮选择先收敛方案，暂不实施；仅跟踪和提交构想，不沿用前三轮的门限委托或生产部署授权。

## 字节范围

- 仅用于 CAR 的 entity-bytes=from:to，闭区间；支持负偏移及结束位置星号。如 0:* 为整文件，-1024:* 为末尾 1024 字节，499:-1000 使用相对文件尾的终点。
- entity-bytes 隐含并优先使用 entity；合法显式 block/all 被其覆盖，不把范围请求误作 all。scope 本身的错误拼写仍为无效输入。
- UnixFS 文件只返回验证范围所需的祖先索引、路径和数据块；块不可切断，返回的完整块可覆盖范围外的部分字节，但不能附带整个无关文件子 DAG。raw 终点仍须返回其完整单块才能校验 CID。
- 部分越界使用有效交集。用户已选择：预检可确认非空文件范围完全越界时返回 400；空文件或零长度结果返回根到终点的 block 证明。有效语法但起点晚于终点的区间按零长度处理，不混同于参数语法错误。
- 非字节实体（目录、DAG-CBOR 对象等）忽略字节选择，保持 entity 语义，不拒绝为“不支持范围”，也不切割序列化 CBOR。内联字节值是否属于可连续读取实体须按固定规范与已有 codec 支持核实，不凭 JavaScript 类型猜测。
- 多区间、空端点、无效数字、重复参数及错误编码返回 400；整数解析须准确，不能用 Number 精度丢失使大偏移变成错误的合法区间。

依据固定
[Trustless Gateway 规范](https://github.com/ipfs/specs/blob/29b7640c6517a03852a5a7958a85e3f89657050a/src/http-gateways/trustless-gateway.md)
的 entity-bytes 条款，实施前对边界 fixture 作逐项规范映射。如核实后发现上述选择与规范强制条款冲突，先讨论并修订，不能以实现便利代替协议。

## 协商与缓存

- 仅支持 CARv1、order=dfs、dups=n，不新增 dups=y、CARv2 或 unknown-order 输出。重复引用仍去重、原始块不改写、identity
  data block 不输出。
- 显式 format 继续优先选择表示；CAR 查询变体覆盖对应媒体参数，返回实际支持组合，必要时提供准确 Content-Location。不能把 format 优先解释为允许将显式请求的变体静默换成其他变体。
- Accept 对支持的候选按质量值及具体程度选择；q=0 不可被宽泛匹配复活，不支持的候选可以退到客户端确实接受的其他候选，没有匹配则 406。对图片/default/raw 的既有行为与必要的协商变化须有明确回归矩阵。
- ETag 必须区分有效字节选择、scope 和表示；HEAD 与 GET 的表示头一致，304 必须验证请求范围仍完整可用，不因旧验证结果省略当前授权或存储检查。非字节实体忽略选择时仍按规范将传入 entity-bytes 纳入表示验证器。

## 资源和已有行为

延续有界预检、既有授权优先、缺失根/路径/存储故障状态码及取消语义。证明与范围合计仍受 256 个唯一块、32
MiB 载荷、单块 2
MiB 限额约束。选择较小字节范围应减少实际读取的 block，而不只是减少最终响应：不能先下载完整文件、再过滤 CAR 就宣称支持高效局部读取。

UnixFS 元数据与 blocksizes 用于定位，但来源不一致、长度溢出或缺少必要索引不能以静默补零、无效成功或读取任意兄弟块掩盖；仅对所需可验证范围宣称完整。验证最小集合、逻辑范围和实际读取集合，保留独立重建及篡改/缺块负例。
