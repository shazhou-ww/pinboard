# 为内容逐项管理私有访问与公开分享

## 问题

Pinboard 的内容字节和 Publication 历史目前公开，作者无法逐项控制读取与下载。权限管理需要融入现有内容墙和阅读详情，而不是挤占预览或分散到多个操作页面。

## 结果

固定 Pin 和 Publication 各自支持公开／私有，新建默认私有；只有所属账号及其受限授权 Agent 能读取私有内容。采用已细化的 [UX 交互说明](UX.md) 与 [现状／提案 Mockup](pinboard-access-ux.html)，明确显示权限、版本和分享边界。

## 边界

- Web 权限修改集中在 detail view；Publication 整项设置覆盖当前及全部历史版本，更新、回滚与转换不意外改变权限。
- 私有项元数据保持隔离；相同字节仍有公开引用时不承诺字节保密，转私有不能收回已有下载、缓存及外部副本。
- 第一版不做指定用户共享、密码／限时链接、逐版本权限或原创作者验证；存量公开项迁移策略须在实施前明确。

## 验收标准

- 新内容默认私有，作者在详情中明确确认公开；内容墙与详情符合引用的 UX 说明，保留阅读、版本及下载体验。
- 私有项的完整内容树、块、预览、描述和历史均不可越权读取；知道 CID、创建引用及低权限凭证不能绕过授权。
- 公开项保持匿名读取；取消最后一个公开引用后停止新的服务端匿名读取，失败与不可撤回边界明确告知用户。
