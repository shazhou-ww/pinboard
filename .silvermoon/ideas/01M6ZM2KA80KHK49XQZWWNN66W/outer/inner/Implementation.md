# Implementation

## Steps

### I-S01: 定义权限与兼容规则

明确逐项归属、合法引用、完整内容树、失败写入、删除恢复和共享字节的读取边界；确定存量策略与所需迁移，保留凭证和权限范围限制。

新增 `0009_item_visibility.sql`，为 Pin／Publication 添加有枚举检查的
`visibility`，默认私有；迁移时仅将已存在项回填公开，以保留旧分享链接。读取由存活项及其 DAG 归属授权；回收保留和全局 CID 存储位置不是授权来源。私有 Pin／Publication 分别要求所属账号的
`pins:read`／
`publications:read`；修改权限同时要求相应读、写范围，OAuth 仍仅用于 `/mcp`。

### I-S02: 贯通服务端与客户端交互

迁移包含 `publication_revisions_cid`
索引；上线前核实旧根的完整 DAG 归属回填。Publication 创建／转换及历史写入要求读范围，持久重试先检查当前项是否存活及可读，再读取旧响应，并补充当前权限。MCP
`block_get` 按相同授权根读取原始块，支持受限 OAuth
Agent 读取完整私有 DAG，不开放 HTTP OAuth 凭证；内联单块上限 2
MiB，失败不返回部分字节。

覆盖所有内容、元数据及引用入口的授权和缓存行为；按 [UX 说明](ideal/UX.md)
调整 Web，同步 CLI、MCP、共享契约与直接相关文档。

集中执行块／缩略图／下载及 Publication 元数据授权，先授权再读取存储及处理 HEAD／ETag／304。所有相关响应使用
`private, no-store`；新缩略图与 CLI CAR 请求使用 `access=v1`
避开旧不可变表示。所有新建项私有，转换继承源权限，更新／回滚继承目标权限；私有源加入公开 Publication 前须显式确认字节和描述曝光，并在原子写入谓词中复核。权限管理仅由详情标题行的最左侧锁／地球启动；上传只读说明、成功后打开详情。卡片锁只读且位于名称前；Publication 原叠层图标改为当前
`vN`。

### I-S03: 验证隔离与视觉一致性

补齐跨账号、匿名、受限凭证、共享 CID、历史和缓存测试；在真实 Web 验证桌面与移动布局，执行针对性检查及
`pnpm check`。

使用 Worker 真实 D1／R2 测试、Web 实际交互处理函数和原有 CLI 测试验证；原有公开协议测试须显式建立公开根，不能把失败存储写入当成公开权限。本地真实 Chrome 在 1280／390／320 宽度测量卡片栏高、预览留白、标题同行、溢出与焦点；只读 UI 预览仅证明布局与保存失败，不冒充生产登录。证据分别见
[浏览器测量](AccessVisual.json) 与 [实施验证](AccessEvidence.md)。
`scripts/access-http-check.mjs`
仅消费操作者明确提供的真实范围凭证，创建唯一前缀内容，不插入账号、令牌或伪造会话；缺凭证时明确报告未覆盖。

## Acceptance criteria

### I-AC01: 无读取与引用旁路

通过授权矩阵及失败写入测试证明私有 DAG、块、预览、描述、历史、HEAD／304 和下载不可越权读取，凭 CID
Pin、单块补齐及 Publication 引用不能自行获取权限。

以 `apps/worker/test/access.test.ts`
的匿名／其他账号／只读／仅上传矩阵及存储读取 spy 证明授权顺序；结合既有 DAG、Publication、OAuth、恢复与 GC 回归测试证明合法完整上传、存量存储兼容与凭证资源限制不变。

### I-AC02: 交互满足细化要求

通过组件测试和浏览器测量证明私有锁位于 info
bar 最前面且不改变 preview 间距或栏高；当前版本号替换卡片图标，详情移除类型 icon 并在标题同一行最左侧提供可点击权限图标；上传和更新不直接修改权限。

`apps/web/test/access.test.tsx`
实际触发确认、复制、保存失败和重试；取消及失败不更新状态，重试再次确认。非作者图标只读，复制私有链接不授权。本地 Chrome 逐宽度比较移除锁前后的栏高与 preview
padding，并验证对话框关闭后焦点返回权限按钮；全部历史确认与共享字节提示不可永久跳过。

### I-AC03: 状态与兼容行为可靠

通过共享引用、公开转私有、保存失败、版本更新回滚及恢复测试证明权限一致、失败保留原状态、存量按已定策略迁移，客户端凭证边界不变；完整检查通过。

生产迁移、旧 CDN 缓存清理、真实第二账号及外部 MCP 客户端验证由父任务在独立授权后执行；本契约只记录可重复的本地实施证据，不记录生产结果或部署授权。

### I-AC04: 最终候选完整检查

最终候选必须运行并通过
`pnpm check`；合入并发变更或修改候选后重新执行。采用既有 CI 的受保护 Windows 夹具路径，不降低原凭证保护或覆盖率要求。通过完整命令退出码、各测试／构建／类型检查结果及四项远端 CI 矩阵证明。
