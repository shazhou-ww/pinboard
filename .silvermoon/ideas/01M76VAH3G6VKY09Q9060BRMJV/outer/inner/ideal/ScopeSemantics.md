# 获取范围与已收敛取舍

本文件服务于 Idea.md，不创建第二份契约。当前只准备方案；不实施、不批准生产部署，也不沿用 iteration
1/2 的委托门限审批授权。

## 目标范围

每种 CAR 都先包含验证请求根到路径终点所需的证明，再按下表选择终点内容。省略 dag-scope 等价于显式 all，不再按 iteration
2 的限制拒绝。

| 路径终点          | block                    | entity                                         | all                                          |
| ----------------- | ------------------------ | ---------------------------------------------- | -------------------------------------------- |
| raw block         | 终点块                   | 等同 block                                     | 等同 block                                   |
| UnixFS 文件       | 文件根块，不补齐内容     | 重建完整文件需要的块                           | 终点的完整可达子 DAG                         |
| 普通 UnixFS 目录  | 目录根块                 | 枚举该目录所需的块，不读取子文件内容           | 包含子目录、文件的完整子 DAG                 |
| HAMT 目录         | 终点目录块及既有路径证明 | 完整枚举所需的目录分片，不递归文件和子目录内容 | 完整目录子 DAG                               |
| 非 UnixFS IPLD 块 | 终点块                   | 等同 block                                     | 终点的全部可达链接                           |
| DAG-CBOR 内联值   | 包含该值的块             | 等同 block                                     | 包含该值的证明块，加该值内部链接的可达子 DAG |

内联值是关键边界：请求 `{selected: {link: A}, sibling: B}`
的 selected，all 只能递归 A，不能因为 selected 与 sibling 位于同一 CBOR 块而递归 B。内联标量没有额外链接；请求本身仍通过包含它的块验证。

HAMT
entity 可以包含必要的多个分片，但不能为了判定每个条目类型而顺带读取子文件块。目录条目的名称及 CID 已足以证明枚举；完整读取子项属于 all。普通 IPLD
entity 等同 block，不能误当 UnixFS 文件递归扩展。

## 已确认的取舍

### 有界预检优先

用户已选择延续 iteration 2 的有界预检。CAR
GET、HEAD 与 304 在成功前验证完整请求范围的可用性及块哈希；不会先返回 200 再把缺块伪装成完整结果。取消和错误必须释放读取资源，root 缺失、路径缺失与存储故障沿用既有权限优先语义。

代价明确：CAR HEAD/304 也可能读取整个请求范围，最坏触及 32
MiB 载荷，不承诺廉价元数据探测；已有 raw
HEAD 的元数据优化不变。流式遍历和中途缺块恢复不是本轮交付。

### 不启用整包 CAR 快路径

用户已选择本轮不复用存储归档直接返回的快路径。不同请求的路径、范围、CID 版本、DFS 顺序、去重及证明都必须由统一流程保证，不能仅因存在完整归档而输出额外块。既有自定义完整 CAR 导出保持原样。

未来若优化，须另行证明与准确请求表示等价；本轮不预先增加开关或优化框架。

## 一致性与资源边界

- 沿用 CARv1、order=dfs、dups=n，不在本轮扩展协商组合。全响应按规范化 CID 去重，路径证明与终点范围共享同一预算。
- 既有单块 2 MiB、256 个唯一块、32 MiB 块载荷上限不放宽；CAR
  framing 不冒充块载荷，也不能将 32 MiB 载荷限制说成峰值内存限制。
- 默认 all 与显式 all 的表示和 ETag 一致；不同 scope 的 ETag 区分，GET/HEAD/304 不因缓存条件省略范围可用性验证。
- 保留根、路径、图片及 raw 的既有授权与选择规则。已支持的 CAR
  all 不再因范围不支持而回退 raw，但不借此改写现有跨格式权重策略。
- 仍限于现有 raw、DAG-PB/UnixFS、DAG-CBOR 能力，不扩展非 UnixFS
  DAG-PB 字段路径、符号链接跟随、IPNS、entity-bytes 或 HTTP
  Range。identity 探针在各支持 scope 下保持有效且不输出 identity data block。

## 实施前须保留的风险检查

当前路径解析只返回证明块，内联终值停留在局部遍历上下文；扩展范围时必须保留真实终点，不能用“最后读到的 CID”代替内联值语义。现有完整 DAG 遍历可作为先例，但不能直接照搬其顺序、终点语义或错误码。

预检、块集合与 CAR 编码可能同时保留多份缓冲；必须验证临界合法输入在 Worker 内存和 D1/R2 预算下可行，不能仅验证小 fixture。若与现有限额冲突，应回到方案讨论，不静默降低限额、扩大预算或跳过测试。完整负载隔离与运营保障仍属于 iteration
5，不在此预先承诺未测指标。
