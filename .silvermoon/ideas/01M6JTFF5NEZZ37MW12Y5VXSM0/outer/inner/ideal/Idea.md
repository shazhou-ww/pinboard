# 用轻量 CLI 完成 Pinboard 上传与管理

## 问题

标准 Kubo 的远程 pin 命令只提交 CID，不能直接满足本服务的主动上传工作流；手写认证和 HTTP 上传命令又过于繁琐。仅为封装上传而要求安装 Kubo，会引入不必要的运行依赖。

## 结果

提供简短、可脚本化的 Pinboard
CLI：直接封装现有 API，上传文件、目录和 CAR，并管理账户 pin，无需安装 IPFS 可执行文件或运行 daemon；目录编码复用 Web 使用的成熟库与共享逻辑。

## 边界

- 保持 Worker + R2、主动上传和完整 DAG 校验，不增加服务端 P2P、Kubo
  RPC 或标准远程 pin 服务承诺。
- 不重做 IPFS 底层协议，不依赖 Kubo 可执行文件或 RPC；标准 IPFS 客户端仅作为可选的读取与互操作工具。
- 上传命令即公开发布，不增加公开确认参数或交互；保持现有账户权限与服务端上传校验。本 idea 不授权 npm 发布或生产部署。

## 验收标准

- 未安装 Kubo 时也能通过短命令上传文件、目录和已有 CAR；文件与目录保持 Web 的编码语义，CAR 保持原根 CID。
- 用户能列出、查看及移除自己的 pin，自动化可获得稳定 JSON 与失败退出码。
- 不依赖本地或服务端 IPFS 节点，不泄漏凭据，不改变现有公开内容与校验边界；范围与风险见
  [CLI 设计](CLI-design.md)。
