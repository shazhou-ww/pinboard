# Implementation

本契约是可调整的实施初版；设计范围见 [CLI 设计](ideal/CLI-design.md)，尚未实施。

## Steps

### I-S01: 建立命令与认证边界

在工作区内实现命令解析、配置优先级、安全 HTTP 客户端、JSON 输出与失败退出码；对接已有 pin
API，不新增服务端协议。

### I-S02: 封装隔离的 Kubo 上传流程

在独立临时仓库中离线编码文件及目录，导出完整 CAR，再调用现有上传服务。已有 CAR 直接上传；纳入子进程中断、临时文件清理、限制检查和 CID 一致性。

### I-S03: 补齐验证与使用文档

接入现有工作区检查，为 CLI、Kubo 子进程和 Worker
API 增加针对性验证，并记录安装、公开内容语义和故障恢复。

## Acceptance criteria

### I-AC01: 上传内容与根 CID 一致

真实 Kubo 与本地 Worker 集成验证普通文件、嵌套目录、隐藏文件、空文件、空目录和 CAR 的上传；独立仓库重建后字节一致，返回根 CID 与 CAR 一致。缺失 DAG、超限及不支持输入必须明确失败。

### I-AC02: 认证与自动化行为可靠

测试覆盖最小权限、过期与撤销、分页、公开确认、HTTP 错误、JSON 输出、失败退出码，以及超时后不误报成功、不自动重放写入。凭据不进入 URL、子进程参数或日志。

### I-AC03: 本地隔离与工作区检查通过

验证缺少 Kubo、并行运行、失败及中断清理，确认用户仓库与 daemon 不变；CLI 相关检查和提交前的
`pnpm check` 通过。文档只声明实际验证过的 Kubo 版本。
