# Implementation

## Steps

### I-S01: 明确 raw 与授权行为矩阵

以 [raw 行为与验证矩阵](RawMatrix.md)
中的固定规范版本为依据，保持授权优先：未知或无权读取的 CID 维持 404；已授权但缺块的 only-if-cached 请求为 412；索引归档丢失或截断仍是 503，不为统一状态码改变权限策略。

严格 raw 指显式选择 raw 的响应契约，不指整个路径只返回 raw。保留缩略图 URL、默认图片表示及既有协商策略，不新增域名、配置开关或迁移图片入口。

### I-S02: 补齐实现与回归验证

在根路径拒绝 Service-Worker:
script，不按内容存在性或身份改变拒绝结果。补齐真实 Worker 路由及图片/raw 表示回归测试，同步 README 与 Kubo 文档。普通 HTTP
Range、完整 CORS/预检与跨站私有内容读取不在本轮实现。

## Acceptance criteria

### I-AC01: 协议行为与权限一致

GET/HEAD、条件响应、探测及不同可访问性状态与矩阵一致；真实 Worker 测试证明服务工作线程根注册在内容读取前统一拒绝，无权读取请求不接触块存储。

### I-AC02: 数据及既有体验不回归

原有 raw、存储故障与权限测试保持通过；缩略图 CID 独立校验、图片 URL、显式 raw
GET/HEAD、附件及表示隔离的条件请求有回归证据，文档与矩阵一致。

### I-AC03: 最终候选通过项目检查

最终候选运行并通过 pnpm check，结果记录于
[验证证据](Verification.md)。后续修改候选或合入并发变更后必须重新执行；Silvermoon 检查不替代项目检查。
