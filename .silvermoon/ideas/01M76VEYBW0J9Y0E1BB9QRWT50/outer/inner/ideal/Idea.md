# 网关迭代 5：收口协议兼容性与 Worker 运行保障

## 问题

局部样例和仓库测试不能证明标准客户端兼容性，也不能证明网关负载不会挤占同一 Worker 的业务能力。

## 结果

形成可公开声明范围、以固定版本官方套件和独立客户端复验的非递归 raw/CAR 网关，并具有明确的运行预算与故障证据。

## 边界

- 前置为 [迭代 4](../../../../01M76VCG6S8J2DJXX1BTXY3STN/outer/inner/ideal/Idea.md) 完成；之后单独扩展 IPNS，不以递归回源、DNSLink 或网站托管作为合规前提。
- 固定规范与 gateway-conformance 版本，区分 MUST、SHOULD、可选变体及权限策略；跳过不代表通过，不以宽泛排除隐藏已声明能力的失败。
- 保护 D1/R2 预算、取消、超时及业务可用性；不隐含购买基础设施、数据库迁移、发布标签或生产部署授权。

## 验收标准

- 官方套件中声明范围的适用测试通过；每项能力与结果可追溯，所有排除项都有理由，必需能力不能以跳过代替完成。
- 独立客户端验证缓存、编码路径、CORS/预检、浏览器请求约束及流式错误；普通 raw HTTP Range 与 CAR entity-bytes 分别声明并验证。
- 在事先固定的吞吐、并发、时延及资源阈值下，限流、超时、取消回收和故障观测有效，业务 API 保持可用，且不泄露私有内容。
