## I-S01 / I-AC01：渲染、字体与原生边界

- `preview-pdf.ts` 只接受
  `PreviewFileSource`，返回不引用 WASM 内存的 RGBA。没有 R2、D1、账户或 CID 依赖；原编排继续负责 WebP
  CID、发布与回收。
- 首页白底、旋转、MediaBox/CropBox、极端长宽比例和合法空白页有断言。红蓝几何页与 2×2 嵌入图片用独立预期颜色验证，不只比较同配置渲染哈希。
- 简体“你好世界”、繁体“中文預覽”分别覆盖嵌入和未嵌入字体。每个字的归一化形状与 Pillow
  11.1.0 /
  FreeType 独立产生的固定参考比较，IoU 下限为 0.7；不是“存在非白像素”检查。字体仅来自已授权、固定哈希的
  `DroidSansFallbackFull.ttf`，无系统字体依赖。
- 加密样例由确定性 Standard Security /
  RC4 生成器构造，并断言明确的密码保护原因。AcroForm、XFA、首页注释全部要求外部静态扁平化；已知缺失的未嵌入 Hangul 明确不支持。不声明所有字体或所有缺字都能检测。
- PDFium 3.0.0、WABT
  1.0.39 位于根 catalog；输入、产物、字体和 PNG 胶水 SHA-256 位于
  `apps/worker/assets/preview-assets.json`。构建不依赖会话路径、网络字体或运行时 WASM 编译；完整原生授权来源随仓库保留。

## I-S03 / I-AC03：组合资源、恢复及生命周期

复审发现的“64 MiB
PDF + 已有解码器 + 编码器”不能直接采用。本实现将原生总线性内存固定为：

| 项目                            | 实施结果                                                                   |
| ------------------------------- | -------------------------------------------------------------------------- |
| PDFium / JPEG / PNG / WebP 解码 | 共用一个 32 MiB 宿主内存区，即时独占                                       |
| WebP 编码                       | 独立 16 MiB 宿主内存区                                                     |
| 原生重建                        | 重置相同底层内存；不叠加故障旧堆和新堆                                     |
| PDFium 回调                     | 每实例固定三个槽位；64 次顺序任务表容量保持 3265                           |
| 会话结束                        | 会话引用为空，逻辑窗口为 0；源块缓存由调用者清空                           |
| 强制内存失败                    | 80 MiB 解压内容触发 32 MiB 上限与 native abort，随后正常 PDF、图片继续成功 |
| 图片压力                        | 1,999,396 像素、接近 8 MiB 的随机 RGBA PNG 仍能输出合规 WebP               |
| 原有图片                        | JPEG/PNG/WebP、方向、透明度、降质与缩小回归通过                            |

这项变更明确超出“只抽出像素编码器”：若原有图片解码器继续各自保留堆，再加入 PDF 堆，就不能满足 R4 的组合预算；故障恢复另建堆也会依赖即时 GC。因此选择宿主共用内存，并针对 PNG 分配器保留原始 17 页起点、以虚拟页计数模拟增长至最多 512 页。它是需要复审的原生初始化扩展，不将其描述为无行为风险的简单抽取。

两个准入周期不能混为一谈：`nativeSession`
等待所属操作的初始化、源读取、同步原生调用及清理全部结束，清除 PDF 回调会话后才释放解码内存区；返回 RGBA 已独立复制。**PDF 的 WebP 编码在该 nativeSession 结束后执行**，使用另一内存区，但仍处于外层
`admitPreview`
的源读取至编码/CID 结果生成周期内。图片缩略图路径则目前连编码一起保留 nativeSession。格式切换只能在旧 nativeSession 结束后清零内存并递增 generation；晚到的取消源读取只能取消块流，不能恢复原生调用。

新增 workerd 跨格式竞争回归直接调用 nativeSession 所在路径，避免被外层
`admitPreview` 提前拦截而掩盖问题。测试通过仅测试入口的 service
binding 悬停 PDF 所属请求的 R2 读取，分别覆盖恢复、读取失败和取消：

1. 在尚未释放源读取时，并发图片和 PDF 请求均已返回 busy，generation、owner、occupied 和回调会话状态不变；不是等待释放后的顺序调用。
2. 恢复成功的原 PDF 与独立构造的整张红蓝像素逐字节相同；随后图片切换及再次 PDF 渲染也通过完整像素断言。
3. 取消场景用仅测试入口的 `waitUntil`
   保持原请求运输层 I/O 在响应后存活；先让图片切换内存区，再放行旧读取。生产
   `preview-source.ts` 必须取消晚到、从未消费的块流；通过取消通知和整个 32
   MiB 内存区的前后 SHA-256 相同证明晚到完成未改写新格式的内存。失败场景验证错误退出后也能切换并恢复。

测试门闩仅存在于 Node 侧 Miniflare 服务回调，Worker 钩子仅位于
`test/pdf-entry.ts`；没有添加生产跨请求 Promise、控制 binding 或 HTTP 路由。

PDF 活跃缓冲保守账本约 84 MiB，图片路径约 104
MiB，包含字体、缓存和瞬时复制预留；细项见[运行边界](../../../../../docs/pdf-previews.md)。这不是 isolate 峰值测量，也不把 workerd 本地成功当作生产 CPU/内存保证。平台总体开销、其他请求、CPU 与启动表现仍属于 Outer
World 的独立外部验收。

忙碌任务在原有 D1 租约围栏内延后，不读源、不消耗失败次数，不建立内存等待队列。异步读取有 20 秒截止；同步 WASM 仍不可由 JS 定时器抢占。预览版本 2 对所有格式生效，旧描述保持原文、旧图片在替换失败期间保留。原有租约、并发发布、授权、直接引用、DAG 成员与回收测试继续运行，PDF 子节点也覆盖“只被父 DAG 保留且不创建子 Pin”的回收流程。

workerd 验证账户保护入口、通用 WebP 网关、出版物预览与公开节点描述；转换为出版物并移除账户 Pin 后仍可读取。无新增下载或 Range
API。客户端沿用普通图片组件与居中裁切，只补旧 PDF 缓存重验、pending/failed 使旧缓存失效，以及暂时失败跨退避周期的有界轮询。
