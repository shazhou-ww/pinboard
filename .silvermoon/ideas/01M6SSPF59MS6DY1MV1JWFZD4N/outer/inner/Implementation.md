# Implementation

本契约是准备阶段的轻量初版，构想验收后再细化。技术依据见[技术方案](./ideal/Technical-proposal.md)与[调研证据](./ideal/Research-evidence.md)。

## Steps

### I-S01: 建立有界 PDF 渲染适配层

接入预编译 PDFium
WASM、字体回退和只渲染第一页的像素输出；固定依赖、授权声明、可复现的内存上限产物及校验方式，明确串行调度、失败实例隔离和恢复策略。

### I-S02: 接入局部读取与现有预览流水线

组合 UnixFS 文件区间读取、完整块校验与请求内去重缓存，通过 PDFium 渐进加载接口异步补齐依赖。小文件全读和大文件按需读取共用预算；复用 WebP 编码、发布、生命周期、前端描述和版本升级机制。

### I-S03: 固化回归测试与使用边界

将代表性 PDF 与确定性生成器转为仓库测试，验证读取收益、像素等价、字体、超限恢复、权限和回收，并更新直接相关文档。避免把本地 PoC 的成功当作线上资源验收。

## Acceptance criteria

### I-AC01: 首页与现有图片行为正确

通过像素或等价图像断言证明支持的 PDF 首页正确、WebP 最长边不超过 480px 且不超过 65,536 字节；嵌入和未嵌入的简繁中文样例均有预期结果，现有图片、文本和目录预览回归通过。

### I-AC02: 局部读取有收益且保持完整性

对后续页携带大资源的非线性化样例，局部与全量首页像素一致，实际 R2 读取字节数至少减少 75%；小文件与首页重资源样例不承诺节省。测试同时证明相同块的并发读取合并、损坏块拒绝及读取预算生效。

### I-AC03: 失败可恢复且完整检查通过

测试证明加密、不可用源、分配失败、WASM 异常及同步缓存缺失不会发布成功描述，故障后正常文件仍可生成；内存上限断言、生命周期和授权回归通过，执行仓库要求的
`pnpm check`。总 isolate 内存和线上 CPU 结论留给部署验证。
