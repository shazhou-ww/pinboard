## 执行与证明边界

| 检查             | 本轮安全执行方式                                                        | 能证明什么                                               | 不能证明什么                                                                                     |
| ---------------- | ----------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 少量并发         | 两份不同内容的小 PDF 同时经正常 MCP 上传，查询自己的新源描述与图片      | 服务能接收并完成同时到达的任务；pending/退让能否最终恢复 | 不保证命中同一 isolate，不能直接断言测试触发了本地独占分支                                       |
| 不支持后继续工作 | 上传确定不支持的表单，再生成正常图片/PDF                                | 应用拒绝结果后仍可继续完成正常任务                       | 不在生产制造 native abort；不能替代本地强制内存失败恢复测试                                      |
| 产物与访问边界   | 对新图片执行 GET、条件 GET、原始格式读取、匿名账户入口拒绝检查          | 图片完整性、缓存重验和账户读保护                         | 不删除用户内容验证 GC；真实保留周期及失去引用仍采用既有实现测试与非破坏性检查                    |
| CPU/错误观察     | 对测试时窗按 `pinboard` 服务和可用的 verified keys 查询聚合             | 该窗口内观测到的 CPU/wall time、失败状态及局限           | 无法归因的日志不能称为单个 PDF CPU；没有内存指标时不把 WASM 上限当作峰值                         |
| 普通大文件       | 先检查已配置 CLI/HTTP 上传凭据；如可用，使用原有约 5.76 MB 随机内容样例 | 正常上传与实际物理读取的线上证据（仅在凭据及指标可用时） | CLI 401 不通过旁路数据库或提取 MCP 凭据解决；MCP 2 MiB 内联上限及上下文传输能力不以去重 CAR 偷换 |
| 回退准备         | 只读核对当前部署版本、已知兼容版本及发布流程                            | 恢复路径可以明确描述                                     | 不擅自回滚代码或数据，不把未演练的步骤写成已执行                                                 |
