# Implementation

## Steps

### I-S01: 复测并定位请求成本

复用固定范围 fixture，建立可归因的分段测量与冷热重复基线；改动前确定目标、适用环境及资源预算，有实质语义或架构取舍时先讨论。

### I-S02: 实施有证据支持的最小优化

只优化已证实瓶颈，补充失效、授权、完整性与资源回归；保留未优化路径的正确行为及明确失败，不引入成功形状的降级。

## Acceptance criteria

### I-AC01: 同条件成本达到事先目标

固定 fixture 的多次前后对比达到实施前记录的时延和读取/资源目标；区分冷启动、冷热缓存及统计范围，不以常量或更小样本测试代替收益验证。

### I-AC02: 完整性与访问边界不回归

缺块、损坏、GC、权限撤销、取消、HEAD/304 和 scope/ETag 有针对性测试；临界合法输入和独立客户端验证通过，不放宽限额或跳过验证。

### I-AC03: 最终候选通过完整检查

最终候选运行并通过 pnpm
check；候选变化后重新执行，不以 Silvermoon 元数据检查代替代码与资源验证。
