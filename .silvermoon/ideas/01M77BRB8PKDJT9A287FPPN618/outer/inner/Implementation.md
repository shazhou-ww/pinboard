# Implementation

## Steps

### I-S01: 复测并定位请求成本

优先评估已选最小内存改动的收益上界及遍历正确性，复用失败实验建立同口径基线；区分两个实际 native
arena、分配与存活堆及运行时 backing。当前只有方案评估授权，未授权生产实现。

### I-S02: 实施有证据支持的最小优化

未来另行获准后，仅实施 HEAD/304 完整预检但不保留全载荷、有界单次块缓冲和 GET 逐块解除引用的可行部分；范围/权限/原始校验与失败语义不变，不夹带二次读取或外部缓冲架构。

## Acceptance criteria

### I-AC01: 同条件成本达到事先目标

固定 fixture 的多次前后对比达到实施前记录的时延和读取/资源目标；区分冷启动、冷热缓存及统计范围，不以常量或更小样本测试代替收益验证。

### I-AC02: 完整性与访问边界不回归

缺块、损坏、GC、权限撤销、取消、HEAD/304 和 scope/ETag 有针对性测试；临界合法输入和独立客户端验证通过，不放宽限额或跳过验证。

### I-AC03: 最终候选通过完整检查

最终候选运行并通过 pnpm
check；候选变化后重新执行，不以 Silvermoon 元数据检查代替代码与资源验证。
