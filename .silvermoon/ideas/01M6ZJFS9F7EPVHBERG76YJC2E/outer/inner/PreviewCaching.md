# 详情预览缓存技术方案

本文件支持 [实施契约](./Implementation.md)
的 I-S01、I-S02、I-S03，记录当前建议及需要验证的风险，不是第四份契约，也不代表构想已验收或功能已实现。

## 当前链路与重复加载原因

- [PinPreview](../../../../../apps/web/src/pin-preview.tsx) 先读取
  [PreviewClient](../../../../../apps/web/src/preview-client.ts)
  的缓存，再决定是否请求；同一客户端会合并相同 CID 的在途请求，并批量获取列表预览。
- [preview-cache](../../../../../apps/web/src/preview-cache.ts)
  已有按账号和 CID 隔离的 IndexedDB 描述缓存。正常预览新鲜期为 1 小时，unsupported 为 5 分钟，保留期为 7 天；持久缓存上限为 500 条、2
  MiB，单条 16 KiB，内存上限为 128 条。
- [NodeDescriptionEditor](../../../../../apps/web/src/node-description.tsx)
  每次挂载或切换请求路径都会清空 data，再请求完整 NodeDescription。它没有复用列表缓存；普通详情和嵌套的高级节点查询也没有共享详情请求。
- [NodeDescription](../../../../../packages/contracts/src/index.ts)
  同时包含根 CID、节点 CID、用户描述及其版本、系统预览。CID 固定不意味着整份响应不可变：私有描述可修改，预览生成状态和生成器版本也会变化。
- [私有描述服务](../../../../../apps/worker/src/descriptions.ts)
  每次读取都检查账号拥有的活动根及节点可达性；保存用 expectedVersion 做乐观并发控制。[发布节点接口](../../../../../apps/worker/src/publication-api.ts)
  校验发布版本及节点可达性，已有 ETag 和 public, no-cache。

## 核心选择：展示缓存，不把缓存当作授权

采用“缓存先展示、后台重新验证”，而不是给整个 description
GET 增加一小时内不请求的规则。

每次打开详情仍重新验证完整响应，以获得最新描述、确认根或发布版本仍有效；优化目标是消除重复阅读时的整体 loading，不承诺详情接口零请求。同一上下文的并发读取合并，成功保存的响应直接更新缓存，避免不必要的额外读取。

私有缓存仅在当前已认证账号的会话内使用。服务端授权始终保留；收到 401、403、404 后清除对应受保护展示与缓存。后台验证完成前展示的是本会话此前已获授权的快照，不宣称支持即时撤权感知；若要求完全禁止短暂旧快照，需要先等待授权验证，不能同时保证零等待。

## 缓存分层与键

| 层               | 缓存对象                                       | 键与归属                                                                                                      | 生命周期                                   |
| ---------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 详情内存         | 完整、运行时校验通过的 NodeDescription         | 私有：账号 + rootCid + nodeCid；发布：publicationId + 明确 revision + rootCid + nodeCid，并与私有命名空间隔离 | 当前应用会话；登出或账号切换释放私有缓存   |
| 既有预览缓存     | 稳定的 ContentPreview 描述，不含用户描述或草稿 | 保留账号 + CID 的既有规则；只复用当前账号下的系统预览，不拿它替代根节点授权                                   | 沿用现有 TTL、IndexedDB 校验和容量预算     |
| 浏览器 HTTP 缓存 | 图片等资源字节                                 | 保持资源 URL 与现有服务端缓存策略                                                                             | 交给浏览器管理，不另建 Blob 或原始文件缓存 |

发布链接跟随 current 时，先由现有发布历史链路解析出实际 revision，再构造详情键。不能只使用 publicationId 或字面值 current。发布缓存不得读取私有用户描述，也不复用私有根上下文作为已验证的发布响应。

第一版不将完整 NodeDescription 持久化到 IndexedDB：避免把可变私有描述长期留在设备上，也不升级既有缓存数据库。整页刷新后允许描述等待重新读取；当前账号已缓存的系统预览可先展示，但不能填造用户描述、版本或编辑权限。

详情内存建议采用 LRU：最多 128 条、总计 2 MiB、单条 64
KiB、保留不超过 1 小时；按 UTF-8 序列化字节数计费。64
KiB 为完整响应预留用户描述空间，不能直接套用既有 16
KiB 预览预算。超预算响应正常显示但不入缓存，并明确记录原因。过期数据不用于快速展示。

容量数值是实施初版选择，需要 I-AC03 的精确边界测试确认，不为此引入用户配置项。

## 客户端与组件接线

在应用或页面的稳定所有者处持有详情缓存客户端，避免每次打开对话框新建空缓存。私有所有者随账号会话变化释放；发布页面使用独立的公开命名空间。以显式类型或属性将同一客户端传给普通详情、发布详情和嵌套高级节点查询，保持当前组件模式，不引入第三方查询库。

沿用现有缓存校验、存储错误通知和 previewPollDelay。若需复用现有 PreviewClient 的写入能力，提取或增加受校验的预览写入入口，不直接访问其私有 Map，也不把目录子节点的根授权错误扩散成全账号的 CID 不可用。

详情请求由共享客户端持有在途 Promise；组件关闭只取消自己的订阅，不中止仍有其他读者的请求。客户端释放时中止自身请求并清空内存。缓存失效或保存时推进该键的请求代次，旧 GET 即使晚返回也不能覆盖新 PUT 响应或重新填回已经失效的数据。

### 打开与后台刷新

1. 切换上下文前立即撤下上一节点内容，从同步内存快照初始化当前键，避免先 setData(null) 再用 effect 补回造成闪烁。
2. 若无完整快照，异步读取当前账号的既有系统预览缓存；预览与完整描述的加载状态分开管理，已有预览不依赖 data 非空才能渲染。
3. 发起或订阅当前键的完整 GET。无缓存时显示原有加载状态；有缓存时保留预览，仅表明后台更新。
4. 校验 rootCid、nodeCid 与请求上下文一致，用户 text 为 string 或 null、version 为非负安全整数，并使用共享 isContentPreview 校验预览；无效响应显式报错且不写缓存。
5. 接受最新响应后更新缓存及非编辑状态的展示。pending 或可重试 failed 继续沿用现有轮询间隔和 24 次上限，不把缓存命中当作生成完成。

只有 ready 或 unsupported 的系统预览进入既有稳定预览缓存。pending、failed 可以作为当前会话的状态展示，但不能阻止重新验证或继续轮询；服务端返回这些状态时撤销旧的稳定预览记录。

### 编辑、保存与高级查询

- 后台刷新可以更新预览，但编辑中的 text 不被覆盖。编辑开始时固定本次草稿的基准 version；PUT 的 expectedVersion 必须来自该基准，而不是后台刚刷新的版本。
- 409 明确提示冲突或根失效，保留草稿，不自动重试覆盖服务端内容；用户确认后才能丢弃草稿重新读取。
- 保存或清除成功后，以 PUT 返回的完整响应更新对应键和所有当前读者。嵌套高级查询修改同一节点时，主详情同步得到更新；修改不同节点不串写主详情。
- “Retry description”保留现有丢弃草稿确认，并绕过快照重新读取。“Retry
  preview”触发完整重新验证和必要的既有轮询，而不是再次返回缓存；当前没有单独的重试生成 POST，不添加成功形状的假重试。
- 删除 pin、删除 publication 及账号退出等已有动作需要接通对应失效入口。恢复后以新读取建立快照，不复活之前被撤销的缓存。

## 错误与资源边界

| 情况                         | 展示与缓存处理                                                                           |
| ---------------------------- | ---------------------------------------------------------------------------------------- |
| 网络错误或 5xx               | 已有快照保留，明确显示刷新失败及重试入口；无快照则显示原有错误，不更新缓存时间           |
| 401、403                     | 私有会话失效时清除该会话缓存和读者展示；其他上下文按请求授权范围失效，不影响无关公开缓存 |
| 404                          | 清除当前根/发布版本节点的快照，撤下对应展示，不跨根误删同 CID 的其他有效上下文           |
| 无效 JSON 或响应上下文不匹配 | 显式提示并拒绝写入；不能将不可验证的新响应作为有效数据或让界面看起来刷新成功             |
| IndexedDB 不可用             | 复用现有 console.warn 降级到内存及真实请求，不让预览功能依赖持久存储                     |
| 图片加载失败                 | 保留现有类型封面回退；缓存 URL 描述不等于图片字节已缓存，不掩盖资源不可用                |

blob: 图片只可在产生它的当前生命周期内使用，不写入持久缓存。跨标签页的私有描述变化通过再次打开时的 GET 发现；第一版不新增跨标签消息总线、Service
Worker 或离线编辑。

本优化不改服务端 API、授权、缓存头、预览生成器或同源 /api/* 路由。发布节点的 ETag 继续使用既有浏览器行为；若以后显式处理条件请求，必须正确还原 304 对应快照，不能把空 body 当作 NodeDescription。

## 验证矩阵

| 场景                                    | 证明方式                                                                           | 对应标准       |
| --------------------------------------- | ---------------------------------------------------------------------------------- | -------------- |
| 关闭后重复打开同一详情，GET 被人为延迟  | 组件断言预览在后台响应前已出现，且不出现整体 Loading content；在途请求次数验证去重 | I-AC01         |
| 无完整内存快照、仅有 IndexedDB 系统预览 | 组件断言预览与描述独立加载，不伪造 user.version 或提前开放未经验证的编辑           | I-AC01、I-AC02 |
| 同 CID 属于不同根；发布 v1/v2；账号切换 | 使用不同描述、预览和响应时序，断言正确键隔离、旧请求不回填                         | I-AC02         |
| 编辑期间刷新、PUT 后旧 GET 返回、409    | 断言草稿与基准版本保留，保存响应不被旧请求覆盖，冲突明确提示                       | I-AC02         |
| pending、failed、重试及后台 5xx         | 假时钟验证既有 2 秒或 30 秒间隔、24 次上限、强制重新验证及错误可见                 | I-AC02、I-AC03 |
| 401/403/404、删除与账号退出             | 断言缓存及读者展示失效，晚到请求不能复活；无关根及公开上下文不被误删               | I-AC02         |
| LRU、总字节数、单条字节数、TTL 边界     | 精确测试 128 条、2 MiB、64 KiB、1 小时边界及超限日志；回归既有预览缓存测试         | I-AC03         |
