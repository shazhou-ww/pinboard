# Implementation

本文件是准备阶段的轻量初版。2026-11-07，[PDF 首页预览](../../../01M6SSPF59MS6DY1MV1JWFZD4N/outer/inner/Implementation-evidence.md)已完成实施并进入部署验收；后续以其已合入主线的实际代码为基线。本轮仍只维护文档，不因依赖完成而自动接受本 Idea 或开始编码。

## Steps

### I-S01: 统一协议与兼容转换

前置条件满足后，刷新[现状基线](./ideal/02-Current-preview-protocol.md)，核实消费者并确定最小过渡策略及退出条件；再依据[3 号设计](./ideal/03-Normalized-preview-design.md)统一契约、描述组装和 API 消费边界，不改变格式渲染器职责。

### I-S02: 接入共享展示与缓存

按设计接入物料与原类型共同决定的共享展示、无物料类型封面、状态联合校验和缓存结构切换；覆盖 Pin、Publication、节点详情及开发样例，不复制 PDF 渲染逻辑或新增类型专用协议。

### I-S03: 验证兼容与失败路径

按设计验证矩阵运行针对性测试、浏览器检查和仓库
`pnpm check`，保留已有展示与内容安全行为。

## Acceptance criteria

### I-AC01: 协议可独立表达类型和物料

以类型校验、描述生成及 API 测试证明原类型与物料可独立表达，非法状态组合被拒绝，PDF 渲染器没有新增对公开协议的依赖。

### I-AC02: 所有展示入口保留类型语义并一致降级

以同一 image 物料搭配 PDF、图片和未知类型的组件测试及浏览器检查，证明 PDF 首页有文档视觉身份、普通图片不带文档标识、未知类型不遮挡物料；三类入口均无物料时显示图标且失败可识别。文本、目录、长名称和暗色模式保持可用，具体场景以设计验证矩阵为准。

### I-AC03: 缓存升级与现有行为可回归

以重建、缓存及已确定的客户端过渡测试证明旧结构不会混读、旧 unsupported 不永久遮挡新物料、授权失效移除旧展示；`pnpm check`
通过。
