# Implementation

本阶段实现已接受的[统一预览设计](./ideal/03-Normalized-preview-design.md)，以已合入的 PDF 像素渲染为基线。范围限于协议、编排、消费边界与共享展示，不修改理想世界、生产数据、数据库 schema 或发布流程。实现验证结果记录在
[Implementation-evidence.md](./Implementation-evidence.md)，不代表 implementation/deployment
acceptance。

## Steps

### I-S01: 统一协议与一次性切换

依据[3 号设计](./ideal/03-Normalized-preview-design.md)统一契约、描述组装和所有 API 消费边界，复用现有生成版本重建机制，完成缓存一次失效；必要的数据处理限定为预览派生数据，不维护旧协议兼容，不改变格式渲染器职责。

共享契约导出 `PreviewMaterial`
与运行时校验；D1 描述读取、私有批量客户端、公开 Publication 与节点描述使用同一校验。生成版本由 2 升至 3，IndexedDB 由 1 升至 2 并清空旧描述 store；保留原始内容和现有缩略图引用回收机制。

### I-S02: 接入共享展示与缓存

按设计接入共享渲染和外层布局，采用 PDF 悬浮纸页；无物料或图片加载失败时显示类型图标，不新增预览失败提示 UX。覆盖 Pin、Publication、节点详情及开发样例，不复制 PDF 渲染逻辑或新增类型专用协议。

PDF 图片使用共享 `Thumbnail`
与上方标识/纸页两行布局；PDF 卡片把底部信息条置于独立自适应行，而非覆盖纸页，并以 280px 最小高度避免窄屏展开时把页面压得过小。卡片宽度明确限定为所属 grid
track 的 100%，不能由最小高度和首选宽高比反推更宽的卡片。图片失败仅存于当前组件，按物料 CID/URL 重置，成功加载可恢复；请求和协议错误保留显式错误处理。节点后台轮询的临时 500/网络失败保留有效描述及未保存草稿，401/403/404 或非法协议则清除旧数据。

### I-S03: 验证升级与展示规则

按设计验证矩阵运行针对性测试、浏览器检查和仓库
`pnpm check`，保留已有展示与内容安全行为。

## Acceptance criteria

### I-AC01: 协议可独立表达类型和物料

以类型校验、描述生成及 API 测试证明原类型与物料可独立表达，非法状态组合被拒绝，PDF 渲染器没有新增对公开协议的依赖。

### I-AC02: 所有展示入口保留类型语义并一致降级

以组件测试及浏览器检查证明悬浮纸页、左上角 PDF 标识与底部信息条互不遮挡，普通图片和未知类型按设计展示；三类入口的图片加载失败均回类型图标且无失败文案，物料可用后恢复。横竖页及其他场景以设计验证矩阵为准；320px/390px 触屏检查同时断言 viewport/document/body
scrollWidth 与卡片、信息条、grid
track 边界，不能仅证明图片位于纸页容器内。节点编辑从 pending 开始输入草稿后，注入后台轮询临时失败验证表单和草稿保留。

### I-AC03: 一次性切换与现有行为可回归

以重建与缓存测试证明旧结构不会混读，刷新后的客户端正常消费新结构，原始内容不变且授权失效移除旧展示；无需跨版本兼容测试，`pnpm check`
通过。
