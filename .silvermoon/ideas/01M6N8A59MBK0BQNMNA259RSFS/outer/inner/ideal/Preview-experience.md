# 内容预览约定

预览是内容的缩小表达，不是统一的文件图标，也不替代原始内容。卡片沿用底部信息条；名称、可复制的 CID 前缀和大小不重复烘焙进缩略图。更完整的信息和操作仍在详情弹窗中。

## 预览描述与内容类型

预览描述分为 `contentType` 和
`content`：前者决定前端的展示方式，后者携带对应内容或资源引用。不要求所有内容都生成一张图片，也不按原始文件扩展名猜测展示方式。

| `contentType`                             | `content` 的含义                                   |
| ----------------------------------------- | -------------------------------------------------- |
| `image/webp`                              | 真实缩略图的 CID、网关 URL 和宽高                  |
| `text/plain`                              | 有长度上限的纯文本摘录                             |
| `text/markdown`                           | 有长度上限、按安全子集展示的 Markdown 摘录         |
| `application/vnd.pinboard.directory+json` | 有限的文件与子文件夹条目，可附带至多三张子图的引用 |
| `application/vnd.pinboard.file+json`      | 原文件的已知类型、大小等信息，用于通用文件占位     |

上述 `vnd.pinboard.*+json` 是项目拟用的媒体类型名称，不声称已经注册；`+json`
表示 JSON 编码，前面的名称表达语义。JSON 对象直接传输，不再包成 JSON 字符串。

预览状态独立为 `pending`、`ready`、`unsupported` 或 `failed`，不挤进
`contentType`。截断或采样应显式标记为
`truncated`，不能让用户误以为看到了全部内容。以下为描述形状示例，不代表接口已实现：

```json
{
  "status": "ready",
  "contentType": "text/markdown",
  "content": "# 标题\n\n这是一段**原内容摘录**。",
  "truncated": true
}
```

```json
{
  "status": "ready",
  "contentType": "application/vnd.pinboard.directory+json",
  "content": {
    "entries": [
      { "name": "README.md", "kind": "file" },
      { "name": "photos", "kind": "directory" }
    ]
  },
  "truncated": true
}
```

`application/vnd.pinboard.file+json` 的 `content.mediaType`
描述原文件类型，与外层预览的 `contentType`
不同。只有可靠识别的信息才能显示；未知类型不猜测。缺少实际预览能力时，文件信息占位不能伪装成
`ready` 的真实内容预览。

## 图片与按 CID 交付

使用原图生成缩略图，保留可辨识的主体和原始比例信息；卡片可适度裁切，但不能生成与原图无关的插画。复杂照片、透明图和纵向图片都应有真实示例证明效果，而非只验证单色小图。候选目标为 WebP、长边不超过 480 像素、单张不超过 64
KiB。

`content`
返回缩略图的 CID、URL、宽高，不包含 Base64 或原始 CAR。列表不携带图片 BLOB，浏览器按需从独立、可缓存的同源标准 IPFS
gateway 路径读取缩略图：

```json
{
  "status": "ready",
  "contentType": "image/webp",
  "content": {
    "cid": "<thumbnailCid>",
    "url": "/ipfs/<thumbnailCid>",
    "width": 480,
    "height": 320
  }
}
```

此处的 `contentType`
描述预览资源，不代表包裹描述的 HTTP 响应本身是图片；网关图片响应才交付对应二进制及正确的媒体类型。CID 必须对应按所选 IPFS 编码可验证、可正确还原的缩略图内容，不能将数据库 ID 伪装成 CID。具体编码与现有网关的适配留待实施验证；D1 仍可保存 BLOB，无需改成 Base64 或独立部署新 Worker。

## 文本与文件夹

- 摘录来自真实原内容，不生成新的 AI 摘要。`text/markdown`
  是预览的轻量展示格式，不要求原文件本身是 Markdown；可将忠实摘录整理成有限格式，以较小的存储与传输成本获得清晰、美观的预览，而不是生成图片或传输完整文档。无需富文本时仍可使用
  `text/plain`。
- Markdown 仅使用标题、段落、列表、强调、引用和代码等有限格式。排版不得改写含义、虚构标题或补充原内容没有的结论。不执行原始 HTML、脚本或 SVG，不加载远程图片、嵌入内容或其他外部资源；预览仅作展示，链接以文字呈现，不提供跳转交互。
- 整理普通文本时正确转义 Markdown 特殊字符，不把偶然出现的语法符号当作原内容的排版意图。代码与结构化文本可用代码样式忠实展示；外层使用
  `text/markdown`
  不改变原文件类型。摘录长度与卡片高度有上限，截断标记明确；截断不能破坏安全边界。
- 文件夹首版为只读概览，不提供进入子文件夹的导航。展示少量真实文件名、类型与有限层级，不把底层存储节点当作文件条目。含图片的文件夹可使用至多三张子图组成概览，而不是下载或展示所有文件。
- 只有完整、准确的统计才能标为总数；采样结果应明确标识，不把已读取数量当成全部内容。

## 按实际内容展示

CAR 是归档格式，DAG 是底层存储概念，都不作为内容墙上面向普通用户的预览分类。文件分块不等于文件夹，也不应因此显示节点关系图。通过协议导入并验证的 CAR 按已识别的根内容展示：

- UnixFS 图片文件：图片缩略图。
- UnixFS 目录：文件夹概览。
- 文本文件：纯文本或有限富文本摘录。
- 其他或无法识别的内容：通用文件信息与明确的预览占位，不猜测用途或虚构摘要。

首版不要求内容墙展示通用 DAG 关系图；技术结构查看如确有需要，另行讨论高级详情，不以改名的方式保留默认节点图。

Web 将 `.car`
当普通文件上传的既有语义不变：不因扩展名自动重新导入，不跟随链接获取本地未存储的内容，也不为预览任意获取远程 CID。

## 共享引用与清理

原内容 CID 与缩略图 CID 是不同身份。相同原内容可被多个账户 Pin；不同原内容也可能生成字节完全相同的缩略图，从而共享同一个缩略图 CID。这是有损预览导致的自然去重，不是哈希碰撞，不能假定一个缩略图只属于一个原内容。

- 记录 Pin、原内容及生成版本到缩略图的有效引用，允许多个原内容共享缩略图；子图预览同样遵循共享引用规则。
- 删除一个 Pin 只解除对应引用，不能直接删除缩略图。只有全部有效引用消失且保留期届满后才可回收。
- 用户直接 Pin 缩略图内容也属于有效引用；重新生成或切换预览版本不能提前破坏仍被引用的旧资源。
- 引用更新与回收必须处理并发，防止新增引用期间误删共享资源；具体事务与任务机制留待实施。
- 缩略图及共享元数据不得携带账户私有 Pin 名称、凭据或其他账户私有字段。文件夹内原有文件名属于内容本身，不与账户私有标签混为一谈。
- 按 CID 提供网关访问不授权抓取任意远程内容，也不弱化现有管理接口授权。回收服务端资源不等于能即时撤回浏览器、网关缓存或他人已经保存的副本。

## 暂不承诺的类型

PDF 首屏、视频帧和音频波形需要额外的解析或渲染能力。首版允许明确的类型占位；不能把这些能力当作现有图片缩放服务已经提供的功能。

## 不可用状态

区分待生成、不支持和生成失败。没有预览时保留类型占位及原因，不偷偷回退到浏览器下载原始 CAR；用户仍可主动下载原内容。

## 后续细化边界

首版预览是展示而非完整文档阅读器或文件浏览器；可点击链接与子文件夹导航不在本次范围。精确摘录长度、文件夹条目与层级上限、保留期、CID 编码和可靠异步任务机制在实施阶段细化；费用、生产迁移及部署仍须独立的明确授权。
