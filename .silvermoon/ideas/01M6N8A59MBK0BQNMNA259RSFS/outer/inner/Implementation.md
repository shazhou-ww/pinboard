# Implementation

本契约为准备阶段的可调整初版。体验目标以[构想契约](ideal/Idea.md)及其内容预览约定为准。

## Steps

### I-S01: 定义按 CID 共享的预览存储与接口

D1 保存预览状态、生成版本、类型描述及图片 BLOB；不存 Base64，不混入账户 Pin 名称。图片暂定长边不超过 480 像素、WebP 编码及 64
KiB 硬上限，其他概览使用受限的类型化数据。统一描述使用 `contentType` 与
`content`，状态单独表达；列表不携带图片字节，图片以缩略图 CID 和同源标准网关 URL 交付。验证缩略图 CID 编码与现有网关兼容，允许不同原内容去重到同一缩略图并维护有效引用。

### I-S02: 实现受限、可重试的内容预览生成

优先复用现有 Worker 处理生成任务，而非立即增加独立部署服务。为图片、纯文本、安全的有限 Markdown、文件夹和已导入 CAR 的根内容设计对应生成器；Markdown 可作为非 Markdown 原内容的忠实摘录展示格式，以轻量文字排版替代截图，不改写含义。明确解码、像素、摘录、条目和层级上限。不生成 AI 摘要或默认存储节点图。缩略图超限时降低质量或尺寸，仍不合格则报告失败；不把异步生成失败当成上传失败。

### I-S03: 接通内容墙与全部内容来源

覆盖 Web、CLI、API、MCP 及已有 Pin 的预览获取或补生成路径，替换浏览器完整 CAR 解码。保留当前卡片信息条和详情操作，明确待生成、不支持、失败和可重试状态；更新共享契约、测试和相关文档。

## Acceptance criteria

### I-AC01: 预览存储与网络开销受限

迁移和接口测试证明相同 CID 共享预览、私有标签不进入共享记录、图片字节不超过 64
KiB，列表不携带 BLOB 或 Base64。验证预览类型与内容形状、网关按缩略图 CID 交付可验证的图片。浏览器网络测试证明内容墙只请求预览而非原始 CAR，并验证缓存及未生成状态。

### I-AC02: 各类内容有真实且安全的预览

用复杂照片、透明图、纵向图、纯文本、Markdown、含图片目录、UnixFS
CAR 和无法识别内容样本验证对应表现、准确采样标识及资源上限，不因底层分块显示目录或节点图。覆盖普通文本转为有限 Markdown 排版时的忠实性与特殊字符转义，证明预览只作展示、文件夹不可导航且链接不可点击。测试畸形或超限内容、HTML/SVG、外部链接与图片和伪造扩展名，证明失败明确、不执行上传内容且不自动加载外部资源。

### I-AC03: 所有入口与 Pin 生命周期保持一致

集成测试覆盖各上传来源、已有内容补生成、重复任务、重试、改名、详情、Unpin 和共享引用清理。包括不同原内容生成相同缩略图、缩略图被直接 Pin、版本切换及新增引用与回收并发；仅在全部有效引用消失且保留期届满后回收。既有授权、原 CID 与字节不变。运行项目检查并记录实际结果，不把环境阻塞描述为通过。
