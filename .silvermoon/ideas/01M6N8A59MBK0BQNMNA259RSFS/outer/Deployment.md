# Deployment

本契约区分隔离本地验证与生产落地。实现使用现有 Worker 内的预编译 WASM、D1
BLOB 与既有 R2，不需要 Images
binding 或独立图片服务。隔离验证及恢复顺序见[落地准备记录](Rollout-readiness.md)，本次获准的生产迁移、tag 发布及平台实际执行结果见[生产发布证据](Production-verification.md)；不以本地结果冒充生产证据。

## Steps

### D-S01: 确认图片处理与生成任务的外部条件

确认现有 Worker 计划内真实图片任务的 CPU、内存及任务执行余量；隔离 workerd 的 WASM 编解码证据不能代替生产配额和任务指标。保持不启用 Images
binding、外部转换服务或新增付费计划；确需新增外部资源时另行取得明确授权。

### D-S02: 按现有发布流程准备迁移与恢复

明确 `0005_previews.sql`
在新代码前应用的顺序、原有 Pin 的有界补生成、失败任务重试、预览版本与七天保留期。隔离环境演练后保留恢复依据；本次生产发布及追加式 D1 迁移已获独立授权，允许必要时清理旧测试数据，但优先保留且不重建数据库。迁移仍须独立执行和验证，不能隐含在发布 workflow 中。生产发布仍仅通过获准的 release
tag，普通分支 push 不部署。

### D-S03: 在获准环境验证真实预览体验

通过真实图片及 CAR 样本验证生成、缩略图交付、缓存、授权和共享内容清理，记录实际网络开销与异常恢复证据。使用独立本地测试服务，不修改父会话工作目录或复用其 UI 服务；真实外部验证只在获准环境执行，不能将合成账户夹具当作生产 OAuth 验证。

## Acceptance criteria

### D-AC01: 外部资源与费用得到确认

以实际配置、授权和服务调用证据证明所选处理能力可用，并确认目标 Worker 计划的 CPU/内存配额能承受受限图片任务；不能仅凭本地 dry-run 宣称生产可用。未授权的付费服务和生产变更保持未启用。

### D-AC02: 迁移与异常恢复可验证

在获准环境演练已有内容补生成、失败任务重试和版本切换，证明已有 Pin 与原始内容仍可读，且无需永久删除或修改原 CID。

### D-AC03: 真实客户端仅加载轻量预览

以浏览器网络记录和 Web、CLI、API、MCP 的真实调用证明预览可用且受限，缩略图可经同源标准 IPFS 网关按 CID 读取，内容墙不自动下载原始 CAR 或富文本外部资源。私有标签与凭据未进入公共预览，记录失败占位、跨原内容共享引用、保留期清理及缓存不能即时撤回的边界。
