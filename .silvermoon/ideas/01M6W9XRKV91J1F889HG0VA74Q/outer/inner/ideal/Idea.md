# 用分类导航整理 Settings

## 问题

当前 Settings 把浏览器偏好、Agent
token、OAuth 授权和回收站纵向堆在一个小弹层中，用户难以定位操作，也难以区分设置的作用范围。

## 结果

Settings 分为通用、访问令牌、OAuth 授权及最近删除；通用集中偏好与 MCP 配置说明，两种授权页用搜索在左、操作在右的紧凑工具栏及固定表头表格。

## 边界

- 只重组现有能力，不新增账户设置、永久删除或跨设备偏好同步；顶部仅 Settings，无关闭按钮，外侧点击或 Escape 关闭，忙碌时禁止关闭。
- 保留 token 与 OAuth 的权限、有效期、撤销及一次性密钥展示语义；保持 30 天恢复和公开内容告知。
- 本轮是上线后的设计反馈讨论，只更新独立 HTML 样稿；讨论完成前不实施、不部署。

## 验收标准

- [新版交互样稿](./settings-table.mock.html)展示加高色块、两种授权的紧凑工具栏及独立滚动的固定表头表格，保持分类和外侧关闭。
- 默认不显示过期及已撤销记录，通过一个「显示无效授权」圆角 switch 同时加入；两者无撤销按钮。新建和刷新为右侧圆形图标按钮，搜索与筛选可组合。授权页无底部说明或 MCP
  endpoint。
- [设计说明](./Design.md)明确交互边界、关键状态及待讨论取舍，足以决定是否进入实施。
