# Settings 分类面板设计讨论

## 当前问题与设计方向

现有 [Settings](../../../../../../apps/web/src/manager.tsx)
使用通用弹层，宽度上限为 680px，整个内容区纵向滚动。回收站入口、token 创建表单和列表、OAuth 授权及浏览器偏好同时展开，复杂且低频的内容占据主要空间。

建议保留弹层而非新增全屏设置页：设置是从主画布进入的辅助操作，关闭后应回到原位置。通过一个更宽的双栏面板改善信息结构，而不是仅放大现有长列表。

## 信息架构

| 分类               | 内容归属                                     | 作用范围             |
| ------------------ | -------------------------------------------- | -------------------- |
| 浏览器偏好（默认） | 三种背景配色、公开上传提醒                   | 仅当前浏览器，不同步 |
| 访问令牌           | token 创建/一次性密钥/有效或历史列表         | 当前账户             |
| OAuth 授权         | MCP endpoint、MCP 客户端授权列表、刷新、撤销 | 当前账户             |
| 最近删除           | 现有回收站入口、30 天恢复及公开副本说明      | 当前账户             |

按本轮反馈，将 token 与 OAuth 拆成两个独立一级页面，不再使用「Agent 与连接」父页或连接方式二级 tabs。两者的认证、生命周期、操作和列表各自管理；token 页保留有效/历史列表切换。暂不增加没有对应功能的“账户”“安全”“高级”分类。

MCP
endpoint 只在 OAuth 授权页的列表上方展示，作为客户端连接入口；访问令牌页聚焦令牌管理。此位置调整不改变 endpoint 或 token 的实际使用能力，也不表示 MCP 只支持 OAuth。

## 授权记录列表

页面按授权方式命名为「访问令牌」与「OAuth 授权」，不按 agent、工具或脚本分类；它们都是可能使用授权的客户端。Token 名称只是标签，不证明持有者身份；OAuth 的客户端信息也不是可信认证标记。

两页都采用同一行式列表结构，不用对象卡片或逐对象管理页面：每行左侧是名称、权限及有效期，右侧是状态和撤销操作。访问令牌的每行代表一个 token，OAuth 的每行代表一条客户端授权记录，而非聚合客户端的所有授权。Token 名称与 OAuth 客户端名称保留各自含义，数据模型和撤销操作仍独立。

- 访问令牌以有效/历史列表区分可用、已撤销和已过期记录；历史行只读。完整密钥不能出现在列表中，仍只在创建后一次性展示。
- OAuth 列表展示客户端名称、授权权限、到期时间或无到期时间，提供逐行撤销和列表刷新；不新增 OAuth 历史功能。
- 加载、空列表、失败状态在各自列表区域呈现，失败不能伪装成空列表。名称和权限可换行，窄屏保留逐行阅读顺序和操作，不把列表退化为横向滚动表格。

## HTML 样稿

[打开交互样稿](./settings-panel.mock.html)。纯 HTML/CSS/JS，离线可用，无外部依赖、API、真实凭据或持久化。样稿正文采用中文讨论标签，保留 token、OAuth 等术语；实施时沿用当前产品语言，以 Access
tokens 代替 Agent tokens，不把本构想当成全站本地化需求。

- 桌面：约 1000px 宽、680px 高，左栏 208px；固定 header 只显示 Settings，无副标题、无关闭按钮，右侧详情独立滚动。低高度窗口按视口收缩。
- 640px 以下：同一个面板，导航改为横向可滚动 tabs，详情在其下方；不把左栏压成无法辨认的图标。键盘方向与导航方向同步改变。
- 默认打开浏览器偏好；复杂的 token 创建表单通过“创建 token”展开，而非一进入设置就展示。
- 支持四个一级分类、有效/历史 token 切换、配色预览、公开提醒勾选、模拟回收站及关闭/重新打开。
- 所有数据明确标为示例；创建、撤销和刷新只显示演示提示，不声称调用成功。回收站只展示返回路径，不模拟真实恢复。
- 点击面板外侧或按 Escape 关闭；窄屏仍保留可点击的外侧间距。点击内部空白不关闭，从内部按下后拖到外侧释放也不关闭。

## 行为边界

1. **保存模型**：浏览器偏好仍逐项即时保存，无全局 Save 按钮；token 创建等账户操作仍有明确动作。保存失败必须显示错误，不可让开关误报成功。
2. **分类切换**：在单次打开过程中保留 token 草稿及已生成的一次性密钥，切换后显示未复制密钥提示和返回入口；只有显式 Dismiss 或既有关闭语义才清理。样稿不生成密钥，实施时需测试这一状态。
3. **请求及错误**：保留现有授权约束和忙碌时关闭限制；分类切换不应清除错误或隐藏正在处理的操作。OAuth 加载、空、失败状态须区分，不把“未加载”伪装成“没有授权”。
4. **回收站**：优先保留现有独立回收站视图，而非重复实现整张列表；打开时退出 Settings，返回 Settings 时定位最近删除。仍显示 30 天恢复、最后引用释放后的七天清理宽限及外部副本不可召回；没有永久删除按钮。
5. **无障碍与关闭**：使用有标签的 modal、tablist/tab/tabpanel；单个活动 tab 进入 Tab 顺序，方向键及 Home/End 切换。无关闭按钮，鼠标/触摸通过外侧点击关闭，键盘通过 Escape 关闭；两者都遵守忙碌时禁止关闭的规则。外侧关闭须同时在外侧按下和释放，避免拖动误关闭；焦点限制在弹层并在关闭时返回入口。配色不能仅靠颜色表达选择。

## 待讨论的取舍

- **默认分类**：建议浏览器偏好，因为内容短、风险低，也最符合一般设置预期；若使用反馈表明连接管理更高频，可调整，不按未经测量的频率排序。
- **回收站深度**：建议本轮仅整理入口和返回路径；嵌入完整回收站会增加布局及状态管理范围，不作为第一版前提。

本文件和样稿用于讨论方向，不是已实施或已验证产品行为的声明；实施与发布方案仍可在对应阶段细化。
