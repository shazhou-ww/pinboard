# Deployment

构想与实现已在用户委托主代理验收后通过，本阶段只验证真实外部结果。阶段验收不构成生产发布、真实凭据配置或数据库迁移授权；没有外部证据时不得提交或通过现实世界验收。

## Steps

### D-S01: 准备获授权的验证环境

按[部署指南](../../../../docs/deployment.md)确认 HTTPS 域名、登录回调、授权服务配置和存储需求。在明确获授权的环境验证；如需生产发布或生产 schema 变更，分别取得授权，遵守现有标签发布流程。

- 记录环境来源、实际运行的应用提交、HTTPS `/mcp`
  地址及 Google 回调；授权服务元数据、`AUTH_URL`
  和 SPA 必须同源。复用现有 Google 回调，不新增或复制真实凭据。
- 核对当前数据库迁移账本及已发布候选。0004 和 `0008_oauth_lifetimes.sql`
  已独立授权应用，不重复执行；新增迁移与发布仍须分别授权，不能以普通 `main`
  推送代替发布，也不能修改发布触发规则。
- 确认授权发现路径及 `/oauth/*`
  在静态资产之前由 Worker 处理，同意页不缓存且不泄漏 referrer；为公开动态注册、授权及换码配置适当的限流/滥用防护，记录具体策略而非假定已启用。

### D-S02: 完成真实客户端授权验证

用选定 MCP 客户端和真实浏览器完成授权、工具调用、取消、撤销及到期检查，同时验证既有 Token 客户端。证据记录环境、客户端版本和结果，不记录凭据值。

- 选用 Visual Studio Code + GitHub
  Copilot，记录两者准确版本和 DCR 能力。配置 HTTP
  `/mcp`，不手动填写 Authorization；完成真实 Google 登录，核对账户、未验证客户端、资源及所选权限，再明确同意。回调仍须精确验证，但按当前产品需求不再展示，不能将隐藏误判为验证缺失。
- 用户先指定 Chrome for Testing，随后明确改用已有登录的 Chrome
  profile，不创建隔离配置。保留用户的日常浏览器会话，使用其原浏览器打开，避免以不同版本写入既有 profile。登录由用户手动完成；自动化只操作 Pinboard 页面与正常 OAuth 回调，不操作 Google 凭据，也不通过伪造浏览器身份绕过 Google 限制。官方 MCP
  SDK 的协议烟测须单独标注，不能冒充已通过 VS Code 客户端验证。
- 分别验证只读权限、写权限、取消/关闭页面、切换账户、其他账户的内容、撤销未换取的授权码及已签发凭据。观察 60 秒授权码真实到期，以及新授权默认
  `1d`、可选 `7d` / `30d` / `never` 的同意、换码和管理状态；有限授权返回相应
  `expires_in`，永久授权省略该字段且仍可撤销，无 refresh token。按钮为 Allow /
  Cancel。
- 既有授权保持原到期时间，迁移前未换取的码仍按 3600 秒换码；历史 1 小时证据只能证明既有契约。至少保留一个新默认
  `1d`
  专用授权，记录到期前成功和自然到期后拒绝及重新连接。不得修改生产时钟、数据库到期时间、缩短产品有效期，或把提前撤销、本地模拟当成真实到期；长周期选项未等满须明确区分元数据验证与自然到期验证。
- 验证原 API
  Token 的 MCP 与 CLI 调用。记录每个标准的操作、预期、实际状态、时间及脱敏客户端结果；不保存令牌、授权码、verifier、Cookie、Google 凭据或带凭据的请求 URL。

## Acceptance criteria

### D-AC01: 真实客户端无需手动 Token 即可连接

至少一个记录名称与版本的真实 MCP 客户端，在指定环境完成授权发现、Google 登录、权限同意与获准工具调用，未手动复制 API
Token；保留脱敏的验证记录。

### D-AC02: 实际权限与兼容性符合契约

在同一环境证明取消授权、权限不足、过期及撤销后请求均被拒绝，其他账户的数据不可访问；原 API
Token 的 MCP 调用与 CLI 操作仍可成功。记录观察到的撤销生效边界和失败结果，不以本地测试替代外部证据。
