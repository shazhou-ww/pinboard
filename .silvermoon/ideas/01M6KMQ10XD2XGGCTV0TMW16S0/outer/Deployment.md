# Deployment

构想与实现已在用户委托主代理验收后通过，本阶段只验证真实外部结果。阶段验收不构成生产发布、真实凭据配置或数据库迁移授权；没有外部证据时不得提交或通过现实世界验收。

## Steps

### D-S01: 准备获授权的验证环境

按[部署指南](../../../../docs/deployment.md)确认 HTTPS 域名、登录回调、授权服务配置和存储需求。在明确获授权的环境验证；如需生产发布或生产 schema 变更，分别取得授权，遵守现有标签发布流程。

- 记录环境来源、实际运行的应用提交、HTTPS `/mcp`
  地址及 Google 回调；授权服务元数据、`AUTH_URL`
  和 SPA 必须同源。复用现有 Google 回调，不新增或复制真实凭据。
- 在获授权的数据库应用新增的
  [0004_mcp_oauth.sql](../../../../apps/worker/migrations/0004_mcp_oauth.sql)，再发布已验收的应用候选。生产迁移与标签发布分别授权，不能以普通
  `main` 推送代替发布，也不能修改发布触发规则。
- 确认授权发现路径及 `/oauth/*`
  在静态资产之前由 Worker 处理，同意页不缓存且不泄漏 referrer；为公开动态注册、授权及换码配置适当的限流/滥用防护，记录具体策略而非假定已启用。

### D-S02: 完成真实客户端授权验证

用选定 MCP 客户端和真实浏览器完成授权、工具调用、取消、撤销及到期检查，同时验证既有 Token 客户端。证据记录环境、客户端版本和结果，不记录凭据值。

- 选用 Visual Studio Code + GitHub
  Copilot，记录两者准确版本和 DCR 能力。配置 HTTP
  `/mcp`，不手动填写 Authorization；完成真实 Google 登录，核对账户、未验证客户端、回调、资源及所选权限，再明确同意。
- 分别验证只读权限、写权限、取消/关闭页面、切换账户、其他账户的内容、撤销未换取的授权码及已签发凭据；观察 60 秒授权码到期和 1 小时访问凭据到期后的失败与重新连接。
- 验证原 API
  Token 的 MCP 与 CLI 调用。记录每个标准的操作、预期、实际状态、时间及脱敏客户端结果；不保存令牌、授权码、verifier、Cookie、Google 凭据或带凭据的请求 URL。

## Acceptance criteria

### D-AC01: 真实客户端无需手动 Token 即可连接

至少一个记录名称与版本的真实 MCP 客户端，在指定环境完成授权发现、Google 登录、权限同意与获准工具调用，未手动复制 API
Token；保留脱敏的验证记录。

### D-AC02: 实际权限与兼容性符合契约

在同一环境证明取消授权、权限不足、过期及撤销后请求均被拒绝，其他账户的数据不可访问；原 API
Token 的 MCP 调用与 CLI 操作仍可成功。记录观察到的撤销生效边界和失败结果，不以本地测试替代外部证据。

## 当前验收结论（2026-11-05）

- 用户已委托主代理验收，构想和实现的准确修订已通过并同步至 primary；这不是本阶段的外部证据。
- 尚未获得本轮生产迁移、标签发布或真实凭据配置授权，未执行这些操作；也未配置独立的获授权 HTTPS 验证环境。
- 未取得真实 Google / VS
  Code 授权、实际到期与撤销、跨账户拒绝及原客户端兼容性的外部验证记录。因此 D-S01、D-S02、D-AC01、D-AC02 均保持未完成，不记录
  `submitOuter` 或 `acceptOuter`。
- 下一步需先明确获授权的验证环境；如使用生产，必须另行授权数据库迁移和标签发布。环境就绪并同步本契约的准确修订后，才按上述步骤生成外部证据。
