# 为 MCP 增加 OAuth 授权

## 问题

当前远程 MCP 只能手动配置 API
Token，交互式客户端需要复制和保管密钥。Google 网页登录并不等于已支持 MCP OAuth。

## 结果

用户可从兼容的 MCP 客户端打开浏览器，登录 Pinboard 并确认权限后连接同一个
`/mcp`；CLI、脚本和 Agent 仍可使用现有 API Token。

## 边界

- 两种授权入口共享账户隔离和权限语义，不新增第二套 MCP 工具或放宽服务端授权。
- OAuth 不消除持有者令牌泄露风险；授权必须有明确同意、受限权限、有效期和撤销能力，不能透传 Google 凭据。
- 本轮不增加 CLI OAuth 登录、不替换网页登录，也不自动授权生产部署或数据库迁移。

## 验收标准

- 至少一个明确记录的兼容 MCP 客户端可完成授权发现、浏览器登录和同意，无需手工粘贴 Token 即可调用获准工具；取消授权不建立访问权。
- 未获准、过期、已撤销及其他账户的访问均被拒绝；用户可查看并撤销客户端授权。
- 既有 API
  Token、CLI 环境变量和 MCP 配置保持兼容；用户文档清楚区分两种授权入口。
