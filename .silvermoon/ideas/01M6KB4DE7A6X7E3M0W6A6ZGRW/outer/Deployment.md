# 非生产保留策略验证

## Steps

### D-S01: 验证迁移与定时清理

现有配置仅发现生产绑定及本地 PoC，没有获准使用的远程 staging。采用本次授权的隔离本地 Wrangler/workerd 非生产环境：独立名称、虚构资源 ID、loopback 监听、独立项目内持久化目录和合成账号/凭据；所有 D1/R2 命令显式
`--local`，不新建远程付费资源，不读取生产凭据或用户数据。运行真实独立 Worker 进程，外部 HTTP 调用真实 API 与 scheduled
handler；不以直接导入实现函数、unit tests 或 dry-run 作为本阶段证明。

先将本契约及观测入口同步到 primary 并复核稳定 deploymentRevision，再运行检查。以 0001/0002 存量 CAR
manifest/block index、旧版 raw block 和合成 pin 初始化真实本地存储，应用
`0003_retention.sql`，验证映射、七天安全下限和逐根闭包回填。通过本地 scheduled 事件入口触发已接受的真实 handler；只调整隔离夹具的时间戳，不等待真实保留期或缩短生产宽限期。

`probe-entry.mjs` 仅透传真实 handler，并记录实际 D1/R2
binding 调用与 wall 时间，不添加登录或数据写入捷径。用接近 32 MiB/256
block 的存量 DAG，叠加 50 项扫描、20 项回收和 100 个 token 清理的有界工作量，要求实际 binding 调用不超过 900、单次 wall 时间不超过 30s；同时记录 SQL 语句数及真实批次结果。该测量是本地 workerd 的实际运行预算，不宣称验证 Cloudflare 账户的远程 CPU 计费/配额。

以隔离数据库约束故障验证真实删除失败日志、持久声明、退避与重试。覆盖共享 CAR/跨账号 DAG 保护、七天前后回收、孤儿扫描及相关索引收敛。迁移与切换期间须停止旧 writer，禁止以旧版 writer 回滚；这次不进行任何生产切换。

### D-S02: 验证用户流程与发布条件

以真实 HTTP 和独立浏览器验证合成账号的 unpin 列表即时移除、共享内容可读、默认有效 token 与历史切换、撤销/过期即时 401，以及匿名、Agent 管理、跨账号写入被拒绝。浏览器使用仅属于本地夹具的合成 session，不执行真实 Google 登录，不添加生产登录绕过。

导出本地 D1、下载并校验 CAR，在停止自有 Worker 后取得一致的 D1/R2 持久化快照；破坏仅属于夹具的引用/内容后实际恢复快照并重新验证。演练停止自有执行器、移除本地 Cron 配置及重启后的只读/鉴权冒烟，形成暂停、监测、恢复与 forward-fix 清单。保留真实失败与授权边界；生产部署、真实 Google 回环和远程 Cron/账户 CPU 配额仍须另行明确授权，不启用默认 push 部署。

## Acceptance criteria

### D-AC01: 外部清理行为可验证

独立非生产 Worker 的外部 scheduled 调用、结构化日志、D1/R2 前后快照证明迁移/回填、存量及共享保护、七天/三十天前后、孤儿和索引回收、失败退避与重试成立；最大夹具的实际调用数量及 wall 时间满足 D-S01 的预算。证据明确区分本地运行结果与未经授权、未验证的远程生产条件。

### D-AC02: 用户流程和运维准备完成

独立浏览器与 HTTP 冒烟证明列表、token 视图和权限正确；实际备份/恢复与暂停演练可复核，监测日志和恢复条件明确。检查记录绑定稳定契约及已接受实现，源代码/Inner/Ideal 不变；所有资源、凭据和被修改的数据仅属于隔离夹具，未经授权不部署生产。
